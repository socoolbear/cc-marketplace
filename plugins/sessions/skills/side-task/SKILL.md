# side-task — 분기 세션을 옆 패널에 띄워 곁가지 작업 맡기기

이 파일은 **부모 세션** 의 절차입니다. 분기 세션의 규칙은 [`references/child.md`](references/child.md) 에 있습니다. 첫 지시가 `분기한 side-task 세션` 으로 시작하는 세션이라면 이 절차를 따르지 말고 그 파일을 따르세요.

스크립트 (실행 시 **절대 경로로 치환**): `$SPAWN` = `${CLAUDE_PLUGIN_ROOT}/skills/side-task/scripts/spawn.sh`

## 1. 띄우기

1. **접미사·작업:** 접미사는 영문 kebab-case (예: `refund`), 세션 이름은 `<부모 이름>-<접미사>` 입니다. 사용자가 주지 않으면 대화에서 정하고 한 줄로 알립니다 (확인은 기다리지 않습니다).
2. **이름 확인:** `ListAgents` 첫 줄에서 부모 (자기) 이름을 봅니다. `<부모>-<접미사>` 가 목록에 이미 있으면 다른 접미사를 묻습니다.
3. **실행 인자** — 한 가지 기준으로 정합니다.
   - 사용자 전역 규칙 (CLAUDE.md 등) 에 세션 실행 명령이 있으면 그 명령의 환경변수는 `--env <이름>`, 플래그는 `--flag <인자>` 로 그대로 넘깁니다 (`-n`·첫 지시 자리는 빼고, 권한 플래그도 빼지 않습니다). 값은 이 세션의 현재 환경에서 읽힙니다.
   - 규칙이 없으면 `ps -o args= -p "$CLAUDE_PID"` 에서 `--dangerously-skip-permissions`, `--permission-mode`, `--model`, `--add-dir` 만 골라 넘깁니다 (`--model=x` 처럼 `=` 로 붙은 형태도 그대로 한 인자).
   - 값이 있는 플래그는 `--flag --model --flag opus` 처럼 인자마다 `--flag` 를 붙입니다.
4. **첫 지시:** 긴 내용은 넣지 않습니다 — 분기 세션은 대화를 이미 이어받습니다. glob (`*`) 을 넣지 않고 브랜치명은 전체를 씁니다.
   ```
   당신은 <부모> 세션에서 분기한 side-task 세션 <이름> 입니다. 분기는 부모가 이미 끝냈으니 side-task 스킬을 다시 실행하지 마세요. 먼저 <child.md 절대 경로> 를 읽고 따르세요. 작업: <작업 설명>
   ```
   부모가 정해 둔 조건 (대상 repo, worktree 위치, 브랜치명) 이 있으면 작업 설명에 함께 적습니다.
5. **실행:**
   ```bash
   bash $SPAWN --parent <부모> --suffix <접미사> [--env NAME]... [--flag ARG]... -- "<첫 지시>"
   ```
   | 종료코드 | 뜻 | 처리 |
   |---|---|---|
   | 0 | stdout `pane=<%N> name=<이름> cwd=<경로>` | 다음 단계 |
   | 2 | 인자 오류 (접미사 형식 등) | 고쳐서 다시 |
   | 3 | tmux 밖이거나 Claude 세션 환경이 아님 | 멈추고 어떻게 열지 묻는다 |
   | 4 | fork 할 대화 기록이 없음 | 멈추고 보고 |
   | 5 | 패널 분할 실패 (공간 부족 등) | tmux 오류와 함께 보고 |
6. **확인:** 몇 초 뒤 `ListAgents` 에서 새 이름과 부모 이름이 **각각 한 번씩** 보여야 합니다. 아니면 `command tmux capture-pane -p -t <pane>` 으로 화면을 보고 원인을 보고합니다.
7. **사용자에게 보고:** 세션 이름 · 패널 id · 작업 한 줄.

## 2. 보고 받기

| 메시지 | 할 일 |
|---|---|
| `[side-task 시작]` | 패널 id 와 worktree 경로를 기억합니다 (닫기 판단에 씁니다) |
| `[side-task 공유]` | 자기 작업에 반영하고, 공유 기록 파일 (notes.md 등) 에 남길 내용이면 남깁니다 |
| `[side-task 질문]` | 답할 수 있으면 `SendMessage` 로 답합니다. 사용자 판단이 필요하면 사용자에게 묻고 그 답을 전달합니다 |
| `[side-task 완료]` | 보고된 커밋·파일이 실제로 있는지 확인하고, 공유 기록 파일에 반영한 뒤 3절로 |

분기 세션에 추가로 지시할 때도 `SendMessage` 로 그 이름에 보냅니다.

## 3. 패널 닫기 판단

완료 보고를 받아도 패널을 바로 닫지 않습니다.

1. 아래가 모두 참이면 닫기 후보입니다.
   - 보고의 남은 일이 `없음` 이다
   - 답하지 않은 `[side-task 질문]` 이 없다
   - worktree 가 있으면 `git -C <worktree> status --short` 가 비어 있다
2. 후보면 분기 세션에 `[side-task 닫기 확인]` 을 보냅니다. 분기 세션이 `닫아도 됨` 이라고 답한 뒤에만 `command tmux kill-pane -t <pane>` 을 실행합니다.
3. 후보가 아니거나 분기 세션이 거절하면 패널을 남기고, 사용자에게 이유를 한 줄로 알립니다.

닫은 뒤 사용자에게 알릴 것:
- 닫은 세션 이름
- 대화 기록이 남아 있어 `claude --resume` 으로 다시 열 수 있다는 것
- worktree 경로·브랜치 (worktree 는 지우지 않습니다. 정리는 사용자나 워크스페이스 도구의 몫)

## 알려진 한계

- 분기 세션은 부모 대화를 통째로 이어받아 부모만큼 찬 상태로 시작합니다. 부모가 이미 compact 에 가까우면 분기 세션도 곧 compact 됩니다. 맥락이 거의 필요 없는 일이면 분기보다 짧은 지시로 새 세션을 여는 편이 낫다고 먼저 알립니다.
- 권한 모드가 다른 세션끼리는 메시지마다 승인 창이 뜹니다. 부모가 띄운 뒤 Shift+Tab·plan mode 로 모드를 바꾼 경우도 같습니다. 보고가 막히면 user settings 의 `crossSessionInbound: "accept"` 를 안내합니다.
- 분기 세션은 부모가 처음 띄워진 디렉토리에서 시작합니다. 부모가 그 뒤 cwd 를 옮겼다면 (`EnterWorktree` 등) 대화를 찾지 못할 수 있습니다 — 6단계 확인에서 드러납니다.
