# side-task — 분기 세션을 패널로 띄워 곁가지 작업 맡기기

이 파일은 **부모 세션** 의 절차입니다. 분기 세션의 규칙은 [`references/child.md`](references/child.md) 에 있습니다. 첫 지시가 `분기한 side-task 세션` 으로 시작하는 세션이라면 이 절차를 따르지 말고 그 파일을 따르세요.

스크립트 (실행 시 **절대 경로로 치환**): `$SPAWN` = `${CLAUDE_PLUGIN_ROOT}/skills/side-task/scripts/spawn.sh`

## 1. 띄우기

1. **접미사·작업:** 접미사는 영문 kebab-case (예: `refund`), 세션 이름은 `<부모 이름>-<접미사>` 입니다. 사용자가 주지 않으면 대화에서 정하고 한 줄로 알립니다 (확인은 기다리지 않습니다).
2. **이름 확인:** `ListAgents` 첫 줄에서 부모 (자기) 이름을 봅니다. `<부모>-<접미사>` 가 목록에 이미 있으면 다른 접미사를 묻습니다.
3. **실행 인자** — 한 가지 기준으로 정합니다.
   - 사용자 전역 규칙 (CLAUDE.md 등) 에 세션 실행 명령이 있으면 그 명령의 환경변수는 `--env <이름>`, 플래그는 `--flag <인자>` 로 그대로 넘깁니다 (`-n`·첫 지시 자리는 빼고, 권한 플래그도 빼지 않습니다). 값은 이 세션의 현재 환경에서 읽힙니다.
   - 규칙이 없으면 `ps -o args= -p "$CLAUDE_PID"` 에서 `--dangerously-skip-permissions`, `--permission-mode`, `--model`, `--add-dir` 만 골라 넘깁니다 (`--model=x` 처럼 `=` 로 붙은 형태도 그대로 한 인자).
   - 값이 있는 플래그는 `--flag --model --flag opus` 처럼 인자마다 `--flag` 를 붙입니다.
4. **첫 지시:** 긴 내용은 넣지 않습니다 — 분기 세션은 대화를 이미 이어받습니다. glob (`*`) 을 넣지 않고 브랜치명은 전체를 씁니다.
   ```
   당신은 <부모> 세션에서 분기한 side-task 세션 <이름> 입니다. 분기는 부모가 이미 끝냈으니 side-task 스킬을 다시 실행하지 마세요. 먼저 <child.md 절대 경로> 를 읽고 따르세요. 작업: <작업 설명>
   ```
   부모가 정해 둔 조건 (대상 repo, worktree 위치, 브랜치명) 이 있으면 작업 설명에 함께 적습니다.
5. **실행:**
   ```bash
   bash $SPAWN --parent <부모> --suffix <접미사> [--env NAME]... [--flag ARG]... -- "<첫 지시>"
   ```
   자리는 스크립트가 고릅니다. 부모 window 에 부모 말고 다른 패널 (자식·분기 세션, 사용자가 연 셸 모두) 이 3개 미만이면 그 window 의 패널로 — 첫 패널은 부모 오른쪽, 그다음은 오른쪽 열을 위아래로 나눕니다. 이미 3개거나 나눌 공간이 없으면 새 window 로 띄웁니다 (더 나누면 폭이 좁아 diff·표가 깨집니다).
   | 종료코드 | 뜻 | 처리 |
   |---|---|---|
   | 0 | stdout `place=<pane\|window> pane=<%N> name=<이름> cwd=<경로>` (Herdr 면 `place=herdr terminal=<주소> name=<이름> cwd=<경로>`) | 다음 단계 |
   | 2 | 인자 오류 (접미사 형식 등) | 고쳐서 다시 |
   | 3 | tmux 밖이고 Herdr 터미널도 아니거나, Claude 세션 환경이 아님 | 멈추고 어떻게 열지 묻는다 |
   | 4 | 이어받을 대화 기록이 없음 (fork 할 부모 대화, 또는 `--resume` 에 준 세션 ID) | 멈추고 보고 |
   | 5 | 패널·window·Herdr 터미널 생성 실패 | tmux·`hc` 오류와 함께 보고 |
6. **확인:** 몇 초 뒤 `ListAgents` 에서 새 이름과 부모 이름이 **각각 한 번씩** 보여야 합니다. 아니면 `command tmux capture-pane -p -t <pane>` 으로 화면을 보고 원인을 보고합니다.
7. **사용자에게 보고:** 세션 이름 · 패널 id · 뜬 자리 (패널인지 window 인지) · 작업 한 줄.

## 2. 보고 받기

| 메시지 | 할 일 |
|---|---|
| `[side-task 시작]` | 패널 id · 세션 ID · worktree 경로를 기억합니다 (3절의 닫기·기록에 씁니다) |
| `[side-task 공유]` | 자기 작업에 반영하고, 공유 기록 파일 (notes.md 등) 에 남길 내용이면 남깁니다 |
| `[side-task 질문]` | 답할 수 있으면 `SendMessage` 로 답합니다. 사용자 판단이 필요하면 사용자에게 묻고 그 답을 전달합니다 |
| `[side-task 완료]` | 보고된 커밋·파일이 실제로 있는지 확인하고, 공유 기록 파일에 반영한 뒤 3절로. 결과가 배포·운영 변경이면 부모가 쓰는 사람의 경로로 직접 QA (화면을 열어 값 확인·실제 호출과 응답) 한 뒤에야 사용자에게 "반영됐다" 고 보고한다. 하위 세션의 QA 보고만 옮겨 전하지 않는다 — 직접 보지 못한 부분은 "하위 세션 확인, 부모 미확인" 으로 나눠 쓴다 |

분기 세션에 추가로 지시할 때도 `SendMessage` 로 그 이름에 보냅니다.

## 3. 닫기 판단과 기록

완료 보고를 받아도 바로 닫지 않습니다. 닫을 수 있으면 기록을 남기고 닫습니다 — 끝난 세션을 띄워 두면 자리를 차지하고 대기 알림이 부모에게 흘러듭니다.

1. 아래가 모두 참이면 닫기 후보입니다.
   - 보고의 남은 일이 `없음` 이다
   - 답하지 않은 `[side-task 질문]` 이 없다
   - worktree 가 있으면 `git -C <worktree> status --short` 가 비어 있다
2. 후보면 분기 세션에 `[side-task 닫기 확인]` 을 보냅니다. 후보가 아니거나 분기 세션이 거절하면 남겨 두고, 사용자에게 이유를 한 줄로 알립니다.
3. `닫아도 됨` 이라고 답하면 **닫기 전에** 태스크 기록 파일의 `## 하위 세션` 절에 한 줄을 남깁니다. 파일은 워크스페이스 규칙이 정한 것 (예: `notes.md`), 없으면 부모 진행 문서입니다.
   ```
   - <세션 이름> · <세션 ID> · <맡은 주제> · <작업 디렉토리>
   ```
   세션 ID 는 `[side-task 시작]` 보고에, 작업 디렉토리는 띄울 때 스크립트가 출력한 `cwd` 에 있습니다 — 재개는 그 디렉토리에서만 대화를 찾습니다.
4. `command tmux kill-pane -t <pane>` 을 실행합니다. 패널로 떴든 window 로 떴든 같습니다 (window 에 그 패널 하나뿐이면 window 도 닫힙니다).

닫은 뒤 사용자에게 알릴 것:
- 닫은 세션 이름과 기록을 남긴 파일
- 후속 문의가 오면 다시 열 수 있다는 것
- worktree 경로·브랜치 (worktree 는 지우지 않습니다. 정리는 사용자나 워크스페이스 도구의 몫)

## 4. 후속 문의 — 닫은 세션 다시 열기

닫은 분기 세션이 맡았던 주제로 후속 문의·추가 작업이 오면 새로 분기하지 말고 그 세션을 다시 엽니다 (새 분기는 그 세션이 한 일을 모릅니다).

1. 태스크 기록 파일의 `## 하위 세션` 절에서 주제가 맞는 줄을 찾습니다. `ListAgents` 에 그 이름이 살아 있으면 다시 열지 않고 `SendMessage` 로 묻습니다.
2. 기록의 값으로 실행합니다. 접미사는 세션 이름에서 `<부모 이름>-` 을 뗀 것이고, 실행 인자 (`--env`·`--flag`) 는 1-3 과 같습니다.
   ```bash
   bash $SPAWN --parent <부모> --suffix <접미사> --cwd <작업 디렉토리> --resume <세션 ID> [--env NAME]... [--flag ARG]... -- "<첫 지시>"
   ```
   첫 지시:
   ```
   side-task 세션 <이름> 을 후속 문의로 다시 열었습니다. 부모는 <부모> 입니다. <child.md 절대 경로> 를 다시 읽고 따르세요. 문의: <후속 문의>
   ```
3. 1-6 처럼 `ListAgents` 로 확인하고, 그 뒤는 2절 (보고 받기) · 3절 (닫기) 과 같습니다. 세션 ID 는 재개해도 그대로라 기록은 다시 쓰지 않습니다.

## 5. Herdr 터미널에서

부모가 tmux 밖의 Herdr 터미널 (`$HC_TERMINAL_ID` 가 있습니다) 에서 돌면 스크립트가 `hc run` 으로 분기 세션을 띄웁니다. tmux 안이면 Herdr 터미널이어도 tmux 로 띄웁니다. 절차는 위와 같고 아래만 다릅니다.

| 단계 | tmux | Herdr |
|---|---|---|
| 자리 (1-5) | 부모 window 의 패널, 또는 새 window | 부모 터미널에 딸린 터미널. 부모 탭에 속하지만 화면 칸은 없고 에이전트 목록에 보입니다 — 화면은 `herdr-app do terminal.peek --terminal <주소>` 로 엽니다 |
| 터미널 이름 | 세션 이름 그대로 | 세션 이름을 소문자로 바꾼 것 (32자 넘으면 앞부분 + 해시). `SendMessage` 주소인 세션 이름은 `<부모 이름>-<접미사>` 그대로입니다 |
| 환경 변수 (1-3) | — | 띄운 터미널은 이 세션의 환경을 물려받지 않습니다. `PATH` 는 스크립트가 늘 넘기고, 분기 세션에 필요한 다른 변수는 모두 `--env` 로 넘깁니다 |
| 화면 확인 (1-6) | `capture-pane` | `hc read <주소>` |
| 기억할 것 (1-7·2절) | 패널 id | 터미널 주소 (`place=herdr` 출력의 `terminal`) |
| 질문 (2절) | 분기 세션이 작업 안의 질문을 자기 패널에서 사용자에게 직접 묻습니다 | 분기 세션은 사용자에게 직접 묻지 않고 전부 `[side-task 질문]` 으로 보냅니다. 부모가 사용자에게 묻고 답을 `SendMessage` 로 전합니다 |
| 분기 세션이 멈춤 | 화면을 봐야 압니다 | 분기 세션이 질문·권한 창에서 멈추거나 끝나면 Herdr 가 부모 입력에 알림을 넣습니다. `hc read <주소>` 로 화면을 보고 사용자에게 전합니다 — `hc send --force` 로 대신 답하지 않습니다 |
| 닫기 (3-4) | `kill-pane` | `hc kill <주소>` 뒤 `hc rm <주소>` |
| 수명 | 부모가 끝나도 남습니다 | 부모 터미널의 프로그램이 끝나면 같이 끝납니다 |

## 알려진 한계

- 분기 세션은 부모 대화를 통째로 이어받아 부모만큼 찬 상태로 시작합니다. 부모가 이미 compact 에 가까우면 분기 세션도 곧 compact 됩니다. 맥락이 거의 필요 없는 일이면 분기보다 짧은 지시로 새 세션을 여는 편이 낫다고 먼저 알립니다.
- 권한 모드가 다른 세션끼리는 메시지마다 승인 창이 뜹니다. 부모가 띄운 뒤 Shift+Tab·plan mode 로 모드를 바꾼 경우도 같습니다. 보고가 막히면 user settings 의 `crossSessionInbound: "accept"` 를 안내합니다.
- 분기 세션은 부모가 처음 띄워진 디렉토리에서 시작합니다. 부모가 그 뒤 cwd 를 옮겼다면 (`EnterWorktree` 등) 대화를 찾지 못할 수 있습니다 — 6단계 확인에서 드러납니다.
