# side-task 분기 세션 규칙

당신은 부모 세션의 대화를 이어받은 **분기 세션** 입니다. 이 파일만 따릅니다. side-task 스킬의 부모 절차 (세션 띄우기) 는 이미 끝났으니 다시 하지 않습니다. compact 뒤에 규칙이 흐려지면 이 파일을 다시 읽습니다.

## 시작할 때

- `ListAgents` 첫 줄에서 자기 이름을, 첫 지시에서 부모 이름을, `echo $TMUX_PANE $HC_TERMINAL_ID $CLAUDE_CODE_SESSION_ID` 로 패널 id 와 세션 ID 를 확인합니다. `$TMUX_PANE` 이 비어 있고 `$HC_TERMINAL_ID` 가 있으면 Herdr 터미널에서 뜬 것입니다 — 아래에서 패널 id 자리에는 그 터미널 주소를 쓰고, 「Herdr 터미널에서 떴으면」 을 따릅니다.
- 부모가 팀을 이끌던 맥락을 이어받았더라도 팀원에게 `SendMessage` 를 보내거나 작업 목록을 고치지 않습니다. 연락은 부모에게만 합니다.

## git

- 부모가 쓰는 checkout 에서 브랜치를 바꾸거나 커밋하지 않습니다.
- git 을 고칠 repo 가 부모와 같은 checkout 이거나 확실하지 않으면 별도 worktree 를 만들어 그 안에서 작업합니다.
  - 위치는 첫 지시나 워크스페이스 규칙 (`CLAUDE.md`·`AGENTS.md`) 이 정하면 그대로 따릅니다. 정하지 않았으면 이 패널에서 사용자에게 묻습니다. 기본 위치는 두지 않습니다 — 하위 디렉토리를 repo 로 세는 워크스페이스 (예: `tasks/<ID>/*/`) 와 부딪힙니다.
  - 브랜치명은 그 repo 의 브랜치 규칙을 따릅니다.
  - `EnterWorktree` 는 쓰지 않습니다. cwd 가 repo 가 아니면 엉뚱한 repo 에 worktree 가 생깁니다.

## 공유 기록 파일

부모가 진행 기록으로 쓰던 파일 (notes.md·PROGRESS·HANDOFF 등, 이어받은 대화로 알 수 있습니다) 은 고치지 않습니다. 남길 내용은 보고에 담고, 기록은 부모가 합니다.

## Herdr 터미널에서 떴으면

사용자에게 직접 묻지 않습니다 (`AskUserQuestion` 도 쓰지 않습니다). 이 터미널은 화면에 칸이 없어 사용자가 보지 못하고, 사용자는 부모와만 대화합니다. 위에서 "이 패널에서 사용자에게 묻는다" 고 한 것을 포함해 물을 것은 모두 `[side-task 질문]` 으로 부모에게 보내고, 답을 기다리는 동안 답과 무관한 일을 계속합니다.

## 보고

`SendMessage` 로 부모 이름에 보냅니다. 아래 다섯 가지만 보냅니다.

| 메시지 | 보낼 때 | 담을 내용 |
|---|---|---|
| `[side-task 시작]` | 작업을 시작할 때 | `<이름> (<pane>)` · 세션 ID, 작업 한 줄, worktree 경로 (브랜치) 또는 `worktree 없음` |
| `[side-task 공유]` | 부모 작업에 영향을 주는 결정·발견이 생길 때 | 그 결정·발견. 진행률만 알리는 메시지는 보내지 않습니다 |
| `[side-task 질문]` | 답이 부모 작업에 영향을 줄 때만 (Herdr 터미널에서 떴으면 사용자에게 물을 것 전부) | 질문. 이 작업 안에서 끝나는 질문은 이 패널에서 사용자에게 직접 묻습니다 (Herdr 터미널이면 이것도 부모에게) |
| `[side-task 완료]` | 끝났을 때 | 결과 한 줄 · 상세 위치 (이 패널 · 진행 파일 경로 · 커밋/PR) · worktree 미커밋 여부 · 사용자 결정 필요 여부 · 남은 일 (없으면 `없음`). 상세는 담지 않습니다 |
| `[side-task 확인 끝]` | 사용자가 이 패널에서 결과 확인을 마쳤다고 하고, 아래 `[side-task 닫기 확인]` 조건이 모두 참일 때 | 세션 이름. 조건이 하나라도 아니면 보내지 않고 사용자에게 무엇이 남았는지 말합니다 |

worktree 를 나중에 만들었으면 `[side-task 공유]` 로 경로를 알립니다.

### 상세 마무리 보고는 이 패널에

`[side-task 완료]` 를 보내기 전에 상세 마무리 보고 (찾은 것 · 한 것 · 확인한 것과 못 한 것 · 다음 할 것) 를 이 패널의 답으로 씁니다. 작업 디렉토리의 repo 가 `.prompts/` 를 git 에서 무시하면 같은 내용을 `.prompts/PROGRESS-<세션 앞 8자>.md` 에도 남깁니다 (부모의 공유 기록 파일과는 다른 파일입니다). 부모는 사용자에게 결과 한 줄과 상세 위치만 전하고, 사용자는 이 패널에서 상세를 보고 이어 묻습니다 (2026-11-26 사용자 결정 — 부모가 상세를 옮겨 전하면 내용이 빠졌다). 사용자의 추가 질문에는 이 패널에서 답하고, 그 답으로 결과가 바뀌면 `[side-task 공유]` 로 바뀐 한 줄을 부모에게 알립니다. Herdr 터미널에서 떴으면 사용자가 이 화면을 보지 못하므로 진행 파일이 상세 위치이고 (`.prompts/` 를 무시하지 않는 repo 면 scratchpad 에 쓰고 절대 경로를 보고합니다), 부모가 넘겨 준 질문에 `SendMessage` 로 답합니다.

## 완료 후

대기합니다. 스스로 종료하거나 패널을 닫지 않습니다. 닫는 것은 부모가 하고, 부모는 닫기 전에 이 세션을 기록해 둡니다.

## 후속 문의로 다시 열렸으면

첫 지시가 `후속 문의로 다시 열었습니다` 이면 닫혔던 세션이 재개된 것입니다. 이 파일을 다시 읽고, 패널 id 를 다시 확인해 (닫기 전과 다릅니다) `[side-task 시작]` 을 다시 보낸 뒤 문의에 답합니다. 끝나면 `[side-task 완료]` 를 보냅니다.

## `[side-task 닫기 확인]` 을 받으면

아래가 모두 참일 때만 `닫아도 됨` 이라고 답합니다. 하나라도 아니면 거절하고 이유를 답합니다.

- 실행 중인 백그라운드 작업이 없다
- 이 세션이 바꾼 파일이 모두 커밋됐다 (커밋하지 않기로 한 것은 그 사실을 완료 보고에 적었다)
- 이 패널에서 사용자와 진행 중인 대화가 없다
- 이 세션이 연 하위 세션 (자식·분기 세션) 이 모두 닫혔다
