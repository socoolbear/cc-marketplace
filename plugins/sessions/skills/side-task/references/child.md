# side-task 분기 세션 규칙

당신은 부모 세션의 대화를 이어받은 **분기 세션** 입니다. 이 파일만 따릅니다. side-task 스킬의 부모 절차 (패널 띄우기) 는 이미 끝났으니 다시 하지 않습니다. compact 뒤에 규칙이 흐려지면 이 파일을 다시 읽습니다.

## 시작할 때

- `ListAgents` 첫 줄에서 자기 이름을, 첫 지시에서 부모 이름을, `echo $TMUX_PANE` 으로 패널 id 를 확인합니다.
- 부모가 팀을 이끌던 맥락을 이어받았더라도 팀원에게 `SendMessage` 를 보내거나 작업 목록을 고치지 않습니다. 연락은 부모에게만 합니다.

## git

- 부모가 쓰는 checkout 에서 브랜치를 바꾸거나 커밋하지 않습니다.
- git 을 고칠 repo 가 부모와 같은 checkout 이거나 확실하지 않으면 별도 worktree 를 만들어 그 안에서 작업합니다.
  - 위치는 첫 지시나 워크스페이스 규칙 (`CLAUDE.md`·`AGENTS.md`) 이 정하면 그대로 따릅니다. 정하지 않았으면 이 패널에서 사용자에게 묻습니다. 기본 위치는 두지 않습니다 — 하위 디렉토리를 repo 로 세는 워크스페이스 (예: `tasks/<ID>/*/`) 와 부딪힙니다.
  - 브랜치명은 그 repo 의 브랜치 규칙을 따릅니다.
  - `EnterWorktree` 는 쓰지 않습니다. cwd 가 repo 가 아니면 엉뚱한 repo 에 worktree 가 생깁니다.

## 공유 기록 파일

부모가 진행 기록으로 쓰던 파일 (notes.md·PROGRESS·HANDOFF 등, 이어받은 대화로 알 수 있습니다) 은 고치지 않습니다. 남길 내용은 보고에 담고, 기록은 부모가 합니다.

## 보고

`SendMessage` 로 부모 이름에 보냅니다. 아래 네 가지만 보냅니다.

| 메시지 | 보낼 때 | 담을 내용 |
|---|---|---|
| `[side-task 시작]` | 작업을 시작할 때 | `<이름> (<pane>)`, 작업 한 줄, worktree 경로 (브랜치) 또는 `worktree 없음` |
| `[side-task 공유]` | 부모 작업에 영향을 주는 결정·발견이 생길 때 | 그 결정·발견. 진행률만 알리는 메시지는 보내지 않습니다 |
| `[side-task 질문]` | 답이 부모 작업에 영향을 줄 때만 | 질문. 이 작업 안에서 끝나는 질문은 이 패널에서 사용자에게 직접 묻습니다 |
| `[side-task 완료]` | 끝났을 때 | 결과 · 커밋/PR · 바꾼 파일 · worktree 와 미커밋 여부 · 부모 기록에 반영할 내용 · 남은 일 (없으면 `없음`) |

worktree 를 나중에 만들었으면 `[side-task 공유]` 로 경로를 알립니다.

## 완료 후

대기합니다. 스스로 종료하거나 패널을 닫지 않습니다.

## `[side-task 닫기 확인]` 을 받으면

아래가 모두 참일 때만 `닫아도 됨` 이라고 답합니다. 하나라도 아니면 거절하고 이유를 답합니다.

- 실행 중인 백그라운드 작업이 없다
- 이 세션이 바꾼 파일이 모두 커밋됐다 (커밋하지 않기로 한 것은 그 사실을 완료 보고에 적었다)
- 이 패널에서 사용자와 진행 중인 대화가 없다
