# child-session — 브리프를 준 새 세션에 흐름 맡기기

이 파일은 **부모 세션** 의 절차입니다. 자식 세션의 규칙은 [`references/child.md`](references/child.md) 에 있습니다. 첫 지시가 `child-session 자식 세션` 으로 시작하는 세션이라면 이 절차를 따르지 말고 그 파일을 따르세요.

스크립트 (실행 시 **절대 경로로 치환**): `$SPAWN` = `${CLAUDE_PLUGIN_ROOT}/skills/child-session/scripts/spawn.sh`

## 0. side-task 와 고르기

| | child-session (새 세션 + 브리프) | side-task (대화 분기) |
|---|---|---|
| 맞는 일 | 몇 시간~며칠 가는 흐름, 또는 나중에 따로 이어 물을 주제 (PR · 문의 답변 · 조사 하나 — 크기와 상관없이) | 한두 시간 안에 끝나는 곁가지 |
| 맥락 | 브리프와 그것이 가리키는 문서만 | 부모 대화 전체 (아직 문서에 없는 맥락이 핵심일 때) |
| 시작 컨텍스트 | 비어 있음 | 부모만큼 찬 상태 — 부모 컨텍스트가 넉넉할 때만 |
| 남는 기록 | 브리프 (계약·재시작 지점) | 대화뿐 |
| 화면 | 부모 window 의 pane (부모 말고 다른 pane 이 이미 3개면 새 window). Herdr 터미널에서는 7절 | 같음 |

맞는 일·맥락·시작 컨텍스트 세 행 중 하나라도 child-session 쪽이면 이 스킬을 쓴다. 리드 세션 안에서 끝나고 결과만 종합하면 되는 일은 자식 세션이 아니라 팀·서브에이전트로 충분하다 (워크스페이스 규칙이 기준을 정하면 그것을 따른다).

## 1. 브리프 쓰기

1. [`references/brief-template.md`](references/brief-template.md) 를 채운다. 결정은 옮겨 적지 말고 결정 로그 경로를 가리킨다.
2. 저장 위치는 워크스페이스 규칙이 정하면 따른다. 없으면 부모 작업 디렉토리의 `.prompts/child-brief-<접미사>.md`.
3. 형제 자식이 여럿이면 공통 부분을 한 파일에 두고 흐름별 절만 나눠도 된다.

## 2. 띄우기

1. **접미사·이름:** 접미사는 흐름을 나타내는 영문 kebab-case (예: `settle`), 세션 이름은 `<부모 이름>-<접미사>`. `ListAgents` 에 같은 이름이 이미 있으면 다른 접미사를 쓴다. `ListAgents` 에 부모 (자기) 와 같은 이름의 세션이 또 있으면 첫 줄의 자기 ref 를 `--parent-ref` 로 넘긴다 — 자식이 보고를 엉뚱한 세션에 보내지 않게.
2. **작업 디렉토리:** 워크스페이스 규칙과 스킬이 실리는 곳 (보통 태스크 루트). 없으면 부모 pane 의 디렉토리.
3. **실행 인자** — 한 가지 기준으로 정한다.
   - **권한 플래그는 넘기지 않는다.** 스크립트가 띄우는 순간 부모 claude 프로세스의 실행 인자에서 `--dangerously-skip-permissions`·`--allow-dangerously-skip-permissions`·`--permission-mode` 를 읽어 붙이고, `--flag` 로 들어온 권한 플래그는 버린다 (예전에 읽은 값을 대화에서 옮겨 쓰면 부모가 모드를 바꿔 다시 뜬 뒤에도 낡은 값이 남았다). 부모 실행 인자에 없으면 붙이지 않아 settings 기본값을 따른다. 읽은 값은 stderr `권한 플래그:` 줄에 나온다.
   - 사용자 전역 규칙 (CLAUDE.md 등) 에 세션 실행 명령이 있으면 그 명령의 환경변수는 `--env <이름>`, 권한 외 플래그는 `--flag <인자>` 로 그대로 넘긴다 (`-n`·첫 지시 자리는 뺀다). 값은 이 세션의 현재 환경에서 읽힌다.
   - 규칙이 없으면 `ps -o args= -p "$CLAUDE_PID"` 에서 `--model`, `--add-dir` 만 골라 넘긴다.
   - 값이 있는 플래그는 `--flag --model --flag opus` 처럼 인자마다 `--flag` 를 붙인다. 넘길 명령을 미리 보려면 `--dry-run`.
4. **첫 지시:** 스크립트가 만든다 (자식 이름, 부모 주소, child.md·브리프 절대 경로). 덧붙일 말이 있으면 `--` 뒤에 짧게 (glob `*` 금지, 브랜치명은 전체) — 내용은 브리프에 쓴다.
5. **실행:**
   ```bash
   bash $SPAWN --parent <부모> [--parent-ref <ref>] --suffix <접미사> --brief <브리프> [--cwd <디렉토리>] [--window] [--dry-run] [--env NAME]... [--flag ARG]... [-- "<덧붙일 지시>"]
   ```
   자리는 스크립트가 고른다. 부모 window 에 부모 말고 다른 pane (자식·분기 세션, 사용자가 연 셸 모두) 이 3개 미만이면 그 window 의 pane 으로 — 첫 pane 은 부모 오른쪽, 그다음은 오른쪽 열을 위아래로 나눈다. 이미 3개거나 나눌 공간이 없으면 새 window 로 띄운다 (더 나누면 폭이 좁아 diff·표가 깨진다). 사용자가 window 를 원하면 `--window`.
   | 종료코드 | 뜻 | 처리 |
   |---|---|---|
   | 0 | stdout `place=<pane\|window> window=<@N> pane=<%N> name=<이름> cwd=<경로>` (Herdr 면 `place=herdr terminal=<주소> name=<이름> cwd=<경로>`) | 다음 단계 |
   | 2 | 인자 오류 (값 빠짐, 접미사 형식, 브리프·디렉토리 없음) | 고쳐서 다시 |
   | 3 | tmux 밖이고 Herdr 터미널도 아님 | 멈추고 어떻게 열지 묻는다 |
   | 4 | `--resume` 에 준 세션 ID 의 대화 기록이 없음 (6절) | 기록의 ID 를 다시 확인 |
   | 5 | pane·window·Herdr 터미널 생성 실패 | tmux·`hc` 오류와 함께 보고 |
6. **확인:** 몇 초 뒤 `ListAgents` 에 새 이름이 한 번 보여야 한다. 아니면 `command tmux capture-pane -p -t <pane>` 으로 화면을 보고 원인을 보고한다.
7. **기록·보고:** pane id 를 부모 진행 문서에 남기고 (compact 뒤에도 닫을 대상을 알도록), 사용자에게 세션 이름 · 맡긴 흐름 한 줄 · 브리프 경로 · 뜬 자리 (pane 인지 window 인지) 를 보고한다.

## 3. 보고 받기

| 메시지 | 할 일 |
|---|---|
| `[시작]` | 계획 요약이 브리프와 맞는지 본다. 어긋나면 바로 `SendMessage` 로 바로잡는다. pane id·세션 ID·worktree 경로를 부모 진행 문서에 남긴다 (5절의 닫기·기록에 쓴다) |
| `[공유]` | 자기 작업과 다른 자식에 반영하고, 기록 파일에 남길 내용이면 남긴다 |
| `[질문]` | 답할 수 있으면 답한다. 사용자 판단이 필요하면 사용자에게 묻고 답을 전달한다 |
| `[진행]` | 기록 파일에 남길 내용만 남긴다 |
| `[완료]` | 보고된 커밋·파일이 실제로 있는지 확인하고, 기록 파일에 결과 한 줄과 상세 위치를 남긴 뒤 사용자에게 아래 「완료를 전하는 법」 대로 전한다. 결과가 배포·운영 변경이면 부모가 쓰는 사람의 경로로 직접 QA (화면을 열어 값 확인·실제 호출과 응답) 한 뒤에야 사용자에게 "반영됐다" 고 보고한다. 하위 세션의 QA 보고만 옮겨 전하지 않는다 — 직접 보지 못한 부분은 "하위 세션 확인, 부모 미확인" 으로 나눠 쓴다 |
| `[확인 끝]` | 사용자가 그 pane 에서 결과 확인을 마쳤고 자식이 닫기 조건을 스스로 점검했다는 뜻이다. `[닫기 확인]` 의 `닫아도 됨` 과 같게 보고 5-3 으로 |

기록 파일 (결정 로그·진행 문서) 은 부모만 고친다. 자식에게 추가로 지시할 때도 `SendMessage` 로 그 이름에 보낸다.

### 완료를 전하는 법

사용자에게는 `<세션 이름> 완료 — <결과 한 줄>, 상세는 pane <id> (<자식 진행 파일 경로·PR>)` 만 전한다. 사용자 결정이 필요하면 `결정 필요 — 그 pane 에서` 를 붙인다. 자식의 상세 보고를 다시 요약하지 않는다 — 요약을 거치면 내용이 빠지고, 사용자는 그 pane 에서 자식에게 바로 물어 확인한다 (2026-11-26 사용자 지적: "작업 내용을 한꺼번에 main 세션으로 전달하니까 내용을 너무 놓치는거 같아"). 배포 변경을 직접 QA 했으면 그 결과 한 줄은 덧붙인다. Herdr 터미널에서 뜬 자식은 사용자가 화면을 보지 못하므로 상세 위치로 진행 파일과 `herdr-app do terminal.peek --terminal <주소>` 를 주고, 사용자가 상세를 부모에게 물으면 자식에게 `SendMessage` 로 넘겨 받은 답을 그대로 전한다.

## 4. 바뀐 규칙·결정 전파

이미 떠 있는 자식은 바뀐 `CLAUDE.md`·`AGENTS.md`·결정 로그를 다시 읽지 않는다. 자식의 일에 영향을 주는 변경이 생기면 `ListAgents` 로 자식을 찾아 `SendMessage` 로 알린다 — 무엇이 바뀌었는지 요지와 읽을 파일 경로를 담는다. 브리프에도 반영한다.

## 5. 닫기 판단과 기록

완료 보고를 받아도 바로 닫지 않는다 — 사용자가 그 pane 에서 상세를 확인하고 자식에게 이어 물을 수 있게 남겨 둔다. 아래 중 하나가 생기면 닫기를 검토한다. 확인을 마친 세션은 미루지 않고 닫는다 — 끝난 세션을 띄워 두면 자리를 차지하고 대기 알림이 부모에게 흘러든다.

- 자식이 `[확인 끝]` 을 보냈다 → 1·2 를 건너뛰고 3 으로
- 사용자가 부모에게 그 세션 확인을 마쳤다거나 닫으라고 했다
- 새 하위 세션을 띄울 자리가 필요하다 (부모 window 의 pane 3개 · 동시 5개 한도). 완료된 세션 가운데 오래된 것부터 닫고, 사용자에게 "확인 전에 닫았고 후속 문의로 다시 열 수 있다" 고 한 줄로 알린다

1. 아래가 모두 참이면 닫기 후보다.
   - 보고의 남은 일이 `없음` 이다
   - 답하지 않은 `[질문]` 이 없다
   - worktree 가 있으면 `git -C <worktree> status --short` 가 비어 있다
2. 후보면 자식에게 `[닫기 확인]` 을 보낸다. 후보가 아니거나 자식이 거절하면 남겨 두고, 사용자에게 이유를 한 줄로 알린다.
3. `닫아도 됨` 이라고 답하면 **닫기 전에** 태스크 기록 파일의 `## 하위 세션` 절에 한 줄을 남긴다. 파일은 워크스페이스 규칙이 정한 것 (예: `notes.md`), 없으면 부모 진행 문서다.
   ```
   - <세션 이름> · <세션 ID> · <맡은 주제> · <작업 디렉토리>
   ```
   세션 ID 는 `[시작]` 보고에 있다. 작업 디렉토리는 띄울 때 스크립트가 출력한 `cwd` 다 — 재개는 그 디렉토리에서만 대화를 찾는다.
4. `command tmux kill-pane -t <pane>` 을 실행한다. pane 으로 떴든 window 로 떴든 같다 (window 에 그 pane 하나뿐이면 window 도 닫힌다).

닫은 뒤 사용자에게 알릴 것: 닫은 세션 이름, 기록을 남긴 파일, 후속 문의가 오면 다시 열 수 있다는 것, worktree 경로·브랜치 (worktree 는 지우지 않는다).

## 6. 후속 문의 — 닫은 세션 다시 열기

닫은 자식이 맡았던 주제로 후속 문의·추가 작업이 오면 부모가 답을 다시 만들지 말고 그 세션을 다시 연다. 대화가 그대로 남아 있어 브리프를 다시 쓸 필요가 없다.

1. 태스크 기록 파일의 `## 하위 세션` 절에서 주제가 맞는 줄을 찾는다. `ListAgents` 에 그 이름이 살아 있으면 다시 열지 않고 `SendMessage` 로 묻는다.
2. 기록의 값으로 실행한다. 접미사는 세션 이름에서 `<부모 이름>-` 을 뗀 것이고, 실행 인자 (`--env`·`--flag`) 는 2-3 과 같다. 자리 규칙도 같다.
   ```bash
   bash $SPAWN --parent <부모> [--parent-ref <ref>] --suffix <접미사> --brief <브리프> --cwd <작업 디렉토리> --resume <세션 ID> [--env NAME]... [--flag ARG]... -- "<후속 문의>"
   ```
3. 2-6 처럼 `ListAgents` 로 확인하고, 그 뒤는 3절 (보고 받기) · 5절 (닫기) 과 같다. 세션 ID 는 재개해도 그대로라 기록은 다시 쓰지 않는다 — 맡은 주제가 넓어졌으면 그 줄만 고친다.

브리프 파일이 없어졌으면 다시 열지 말고 새 자식을 띄운다 (자식 규칙이 브리프를 다시 읽게 한다).

## 7. Herdr 터미널에서

부모가 tmux 밖의 Herdr 터미널 (`$HC_TERMINAL_ID` 가 있다) 에서 돌면 스크립트가 `hc run` 으로 자식을 띄운다. tmux 안이면 Herdr 터미널이어도 tmux 로 띄운다. 절차는 위와 같고 아래만 다르다.

| 단계 | tmux | Herdr |
|---|---|---|
| 자리 (2-5) | 부모 window 의 pane, 또는 새 window | 부모 터미널에 딸린 터미널. 부모 탭에 속하지만 화면 칸은 없고 에이전트 목록에 보인다 — 화면은 `herdr-app do terminal.peek --terminal <주소>` 로 연다. `--window` 는 쓰이지 않는다 |
| 터미널 이름 | 세션 이름 그대로 | 세션 이름을 소문자로 바꾼 것 (32자 넘으면 앞부분 + 해시). `SendMessage` 주소인 세션 이름은 `<부모 이름>-<접미사>` 그대로다 |
| 환경 변수 (2-3) | — | 띄운 터미널은 이 세션의 환경을 물려받지 않는다. `PATH` 는 스크립트가 늘 넘기고, 자식에 필요한 다른 변수는 모두 `--env` 로 넘긴다 |
| 화면 확인 (2-6·알려진 한계) | `capture-pane` | `hc read <주소>` |
| 기록 (2-7·3절) | pane id | 터미널 주소 (`place=herdr` 출력의 `terminal`) |
| 질문 (3절) | 자식이 흐름 안의 결정을 자기 pane 에서 사용자에게 직접 묻는다 | 자식은 사용자에게 직접 묻지 않고 전부 `[질문]` 으로 보낸다. 부모가 사용자에게 묻고 답을 `SendMessage` 로 전한다 |
| 자식이 멈춤 | 화면을 봐야 안다 | 자식이 질문·권한 창에서 멈추거나 끝나면 Herdr 가 부모 입력에 알림을 넣는다. `hc read <주소>` 로 화면을 보고 사용자에게 전한다 — `hc send --force` 로 대신 답하지 않는다 |
| 닫기 (5-4) | `kill-pane` | `hc kill <주소>` 뒤 `hc rm <주소>` |
| 수명 | 부모가 끝나도 남는다 | 부모 터미널의 프로그램이 끝나면 같이 끝난다 |

## 알려진 한계

- 자식은 브리프에 없는 맥락을 모른다. `[시작]` 의 계획 요약을 꼭 확인한다.
- 처음 여는 디렉토리면 자식이 폴더 신뢰 확인 창에서 멈춘다. 2-6 의 `capture-pane` 에 그 창이 보이면 사용자에게 알린다 (부모가 대신 신뢰를 고르지 않는다).
- 권한 모드는 부모가 **켜질 때** 받은 실행 인자를 따른다 — 부모가 켜진 뒤 Shift+Tab·plan mode 로 바꾼 모드는 넘어가지 않는다. 띄운 뒤 자식 화면 아래의 권한 표시를 한 번 본다.
- 권한 모드가 다른 세션끼리는 메시지마다 승인 창이 뜬다. 보고가 막히면 user settings 의 `crossSessionInbound: "accept"` 를 안내한다.
- 부모가 먼저 끝나면 보고가 갈 곳이 없다. 부모를 다시 열면 같은 이름으로 열고, 자식들에게 `ListAgents` 로 확인한 부모 이름을 알린다.
