# child-session 자식 세션 규칙

당신은 부모 세션이 브리프를 주고 띄운 **자식 세션** 입니다. 이 파일과 브리프를 따릅니다. child-session 스킬의 부모 절차 (브리프 쓰기·세션 띄우기) 는 하지 않습니다. compact 뒤에 규칙이 흐려지면 이 파일과 브리프를 다시 읽습니다.

## 시작할 때

1. 첫 지시에 적힌 브리프를 읽고, 브리프의 "먼저 읽을 것" 을 순서대로 읽습니다.
2. `ListAgents` 첫 줄에서 자기 이름을, 첫 지시에서 부모 주소를 (ref 가 있으면 ref 까지), `echo $TMUX_PANE $HC_TERMINAL_ID $CLAUDE_CODE_SESSION_ID` 로 자기 pane id 와 세션 ID 를 확인합니다. `$TMUX_PANE` 이 비어 있고 `$HC_TERMINAL_ID` 가 있으면 Herdr 터미널에서 뜬 것입니다 — 아래에서 pane id 자리에는 그 터미널 주소를 쓰고, 「Herdr 터미널에서 떴으면」 을 따릅니다.
3. 계획을 세우고 `[시작]` 을 보냅니다. 부모는 이 계획 요약으로 브리프를 잘못 읽은 곳을 바로잡습니다.

## git

- 부모나 다른 자식이 쓰는 checkout 에서 브랜치를 바꾸거나 커밋하지 않습니다.
- 브리프가 worktree 를 정했으면 그 안에서만 작업합니다. 새 worktree 가 필요하면 워크스페이스 규칙 (`CLAUDE.md`·`AGENTS.md`) 대로 만들고 `[공유]` 로 경로를 알립니다. 규칙이 없으면 이 pane 에서 사용자에게 묻습니다.
- `EnterWorktree` 는 쓰지 않습니다.

## 공유 기록 파일

부모가 쓰는 기록 파일 (결정 로그·진행 문서 등, 브리프가 가리킨 것) 은 고치지 않습니다. 남길 내용은 보고에 담고, 기록은 부모가 합니다. 브리프가 자기 진행 파일을 정해 줬으면 그 파일만 씁니다.

## 사용자와의 대화

이 흐름 안에서 끝나는 결정은 이 pane 에서 사용자에게 직접 묻습니다. 답이 다른 흐름이나 부모 작업에 영향을 주면 `[질문]` 으로 부모에게 보냅니다.

## Herdr 터미널에서 떴으면

사용자에게 직접 묻지 않습니다 (`AskUserQuestion` 도 쓰지 않습니다). 이 터미널은 화면에 칸이 없어 사용자가 보지 못하고, 사용자는 부모와만 대화합니다. 위에서 "이 pane 에서 사용자에게 묻는다" 고 한 것을 포함해 물을 것은 모두 `[질문]` 으로 부모에게 보내고, 답을 기다리는 동안 답과 무관한 일을 계속합니다.

## 보고

`SendMessage` 로 첫 지시에 적힌 부모 주소 그대로 보냅니다 (같은 이름의 세션이 둘이면 ref 가 없을 때 엉뚱한 세션에 갑니다). 첫 줄에 태그를 둡니다.

| 메시지 | 보낼 때 | 담을 내용 |
|---|---|---|
| `[시작]` | 계획을 세운 뒤 | `<이름>` · pane id · 세션 ID, 계획 요약, worktree 경로 (브랜치) 또는 `worktree 없음` |
| `[공유]` | 다른 흐름·부모 작업에 영향을 주는 결정·발견이 생길 때 | 그 결정·발견 |
| `[질문]` | 답이 부모나 다른 흐름에 영향을 줄 때만 (Herdr 터미널에서 떴으면 사용자에게 물을 것 전부) | 질문과 추천안 |
| `[진행]` | 단계가 끝날 때마다 | 한 일 · 상태 · 막힌 점 |
| `[완료]` | 브리프의 끝맺음 조건을 채웠을 때 | 결과 · 커밋/PR · 바꾼 파일 · worktree 와 미커밋 여부 · 부모 기록에 반영할 내용 · 남은 일 (없으면 `없음`) |

브리프에 형제 세션과 직접 맞출 일이 적혀 있으면 그 이름에 직접 보내고, 결과는 `[공유]` 로 부모에게도 알립니다.

## 규칙·결정이 바뀌었다는 메시지를 받으면

부모가 보낸 변경을 브리프보다 우선합니다. 이미 떠 있는 세션은 바뀐 `CLAUDE.md`·`AGENTS.md` 를 다시 읽지 않으므로, 메시지가 가리킨 파일을 직접 읽습니다.

## 완료 후

대기합니다. 스스로 종료하거나 pane 을 닫지 않습니다. 닫는 것은 부모가 하고, 부모는 닫기 전에 이 세션을 기록해 둡니다.

## 후속 문의로 다시 열렸으면

첫 지시가 `후속 문의로 다시 열었습니다` 이면 닫혔던 세션이 재개된 것입니다. 이 파일과 브리프를 다시 읽고, pane id 를 다시 확인해 (닫기 전과 다릅니다) `[시작]` 을 다시 보낸 뒤 문의에 답합니다. 끝나면 `[완료]` 를 보냅니다.

## `[닫기 확인]` 을 받으면

아래가 모두 참일 때만 `닫아도 됨` 이라고 답합니다. 하나라도 아니면 거절하고 이유를 답합니다.

- 실행 중인 백그라운드 작업이 없다
- 이 세션이 바꾼 파일이 모두 커밋됐다 (커밋하지 않기로 한 것은 그 사실을 완료 보고에 적었다)
- 이 pane 에서 사용자와 진행 중인 대화가 없다
- 이 세션이 연 하위 세션 (자식·분기 세션) 이 모두 닫혔다
