# 브리프 템플릿

부모가 자식 세션을 띄우기 전에 채워 파일로 저장한다. 자식은 대화를 이어받지 않으므로 **이 파일이 자식이 아는 전부**다. 결정의 원문은 옮겨 적지 말고 경로로 가리킨다 — 브리프가 결정 로그의 두 번째 사본이 되면 둘이 어긋난다.

빈 섹션은 지운다. 형제 자식이 여럿이면 공통 부분은 한 파일에 쓰고 흐름별 절만 나눠도 된다.

```markdown
# <태스크> 자식 세션 브리프 — <흐름> (<날짜>)

부모 세션: **<부모 이름>** (같은 이름의 세션이 둘 이상이면 `[ref]` 까지)

## 목표와 범위
- 이 흐름이 끝나면 무엇이 되어 있어야 하나 (한두 줄)
- 맡는 것 / 맡지 않는 것 (다른 자식·부모가 맡는 것)

## 먼저 읽을 것
결정 로그 → 진행 문서 → 계약·설계 문서 순서로 경로만.

## 환경 사실
- 작업할 worktree 절대경로·브랜치 (없으면 만드는 규칙)
- 접근 수단 (dev 환경 주소, 조회 도구, 필요한 로그인)
- 이미 확인된 상태 (배포된 버전, 비어 있는 데이터 등)

## 규칙 (반드시)
- 하지 말 것 (운영 변경, 외부 발송, 특정 repo 커밋 등)
- 확인받을 지점 (워크스페이스 규칙의 배포·외부 발송 기준을 가리킨다)
- 공유 기록 파일: 자식은 고치지 않는다. 자기 진행 파일이 있으면 그 경로

## 진행 방식
1. 맡은 범위의 계획을 세운다
2. 착수 전에 사용자에게 물을 것을 모아 한 번에 묻는다
3. 진행한다. 독립 작업은 병렬로

## 보고
- 부모: <부모 이름>. 태그는 child.md
- 직접 맞출 형제 세션: <이름> — <맞출 일>

## 끝맺음 조건
무엇이 확인되면 `[완료]` 를 보내나 (PR 머지, dev QA 통과, 문서 제출 등)
```
