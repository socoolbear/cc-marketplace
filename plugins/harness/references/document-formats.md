# 문서 표준 포맷 — v2 산출물의 단일 정답

setup 이 생성하고 update 가 비교하는 대상 프로젝트 문서 5종 + 브리지 1종의 표준 골격.
모든 모드는 문서의 "정답" 이 필요할 때 본 파일을 참조한다.

---

## 0. 공통 원칙

| 원칙 | 내용 |
|------|------|
| 재도출 가능하면 쓰지 않는다 | 디렉토리 구조·의존성 목록·아키텍처 개요 서술 금지 — 코드가 정답. 문서에 남는 것은 **함정 (pitfall)·이유 (rationale)·기본값과 다른 관례·이력·용어** 뿐 |
| 한 줄 테스트 | 모든 줄에 대해 "이 줄을 지우면 에이전트가 실수하는가?" — 아니라면 지운다 |
| 갱신 주체 | 작업 에이전트 + 사람 (작업 중 같은 커밋에서). 하네스 모드는 안전망 (audit 이 낡음을 보고) |
| 데이터 성격 | 5종 모두 프로젝트 누적 자산 — update 는 골격 (섹션 구조) 만 보수하고 본문 데이터를 절대 수정하지 않는다 |

---

## 1. `AGENTS.md` — 지도 (≤40줄)

목차이지 백과사전이 아니다. 상세는 `harness/` 문서로 포인터만 제공한다.

````markdown
# {프로젝트명}

{프로젝트 한 줄 설명}

## 검증 명령 (완료 주장 전 반드시 실행 — 이 목록이 검증의 단일 정답)

- 빌드: `{빌드 명령어}`
- 테스트: `{테스트 명령어}`
- 린트: `{린트 명령어}`
- 타입체크: `{타입체크 명령어}`
- 레이어 검사: `npm run check:layers`   <!-- enforcement 활성 시만 -->

## 지식 문서 (필요할 때 읽기)

- 아키텍처 불변 조건 → `harness/ARCHITECTURE.md`
- 결정 이력 (왜 이렇게 됐나) → `harness/ADR.md`
- 용어집 (도메인 용어·표기) → `harness/GLOSSARY.md`
- 교훈 (반복 실수 방지) → `harness/LESSONS.md`

## 경계

- Never: {예: docs/legacy-*/ 수정, 프로덕션 DB 직접 접근}
- Always: {예: 커밋 메시지 한국어}
- Ask first: {예: 공개 API 스키마 변경}

## 문서 유지 규칙

- 아키텍처 불변 조건을 바꾸는 변경은 **같은 커밋** 에서 `harness/ARCHITECTURE.md` 갱신 + `harness/ADR.md` 항목 추가
- 작업 중 거짓으로 판명된 문서 문장은 같은 커밋에서 수정
````

**작성 규칙**:
- 40줄 이내. 초과하면 내용을 harness/ 문서로 내리고 포인터만 남긴다
- "검증 명령" 은 필수 소절 — 해당 도구가 없는 항목은 줄 자체를 제거 (빈 플레이스홀더 금지)
- "경계" 는 최대 5줄. 프로젝트에 실재하는 금지/필수 사항만
- 사용자가 직접 추가한 섹션은 어떤 모드도 수정하지 않는다

## 2. `CLAUDE.md` — 브리지 (1줄)

Claude Code 는 CLAUDE.md 를 읽으므로, 부재 시 다음 한 줄로 생성한다:

```markdown
@AGENTS.md
```

기존 CLAUDE.md 가 있으면 보존하고, `@AGENTS.md` import 가 없다는 사실만 사용자에게 안내한다 (자동 삽입 X).

## 3. `harness/ARCHITECTURE.md` — 아키텍처 불변 조건

**규칙 (불변 조건 + 이유) 만** 담는다. 현황 서술·디렉토리 설명·코드 예시는 금지 — 코드가 정답.

````markdown
# 아키텍처 불변 조건

규칙과 이유만 기록한다. 현황 서술은 쓰지 않는다 (코드가 정답).
불변 조건 변경은 같은 커밋에서 본 파일 갱신 + `ADR.md` 항목 추가.

## 레이어 (허용 import 방향)

| 레이어 | import 가능 | 이유 |
|--------|-------------|------|
| `types` | (없음) | 순수 타입 레이어 유지 |
| `core` | `types` | 프레임워크 독립성 |

## 금지 패턴

- {예: `core/` 에서 React import 금지 — 프레임워크 독립성}

## 타입 경계

- {예: 외부 API 응답은 `adapters/` 에서 내부 타입으로 변환 — 외부 스키마 변경 격리}
````

- 레이어 표는 `scripts/check-layer-import.js` 의 DAG 와 동기화 (enforcement 활성 시 — `./mechanical-enforcement.md`)
- 레이어 구조가 없는 프로젝트는 "금지 패턴" / "타입 경계" 등 실재하는 불변 조건 섹션만 작성

## 4. `harness/ADR.md` — 결정 이력 (append-only 단일 파일)

````markdown
# 아키텍처 결정 기록 (ADR)

append-only. 발행된 항목의 본문은 수정하지 않는다 (오타 포함 — 번복은 새 항목으로).
번복: 새 항목 발행 + 기존 항목의 상태 줄만 `Superseded by NNNN` 로 변경.
번호: 4자리 zero-padded, 재사용 금지.

## 0001: {결정 제목} — Accepted (YYYY-MM-DD)

### 맥락
{왜 이 결정이 필요했나 — 문제, 제약}

### 결정
{무엇을 어떻게 하기로 했나}

### 결과
{긍정 / 감수하는 것 / 기각한 대안 한 줄씩}
````

**판단 기준 — 전략적 결정만 기록한다**:

| 기록한다 | 기록하지 않는다 |
|----------|-----------------|
| 레이어 구조, 타입 경계, 핵심 의존성 선택, 금지 패턴, 데이터 정책 | 구현 디테일, 쉽게 되돌릴 수 있는 선택, 코드에서 자명한 것 |

**상태 집합**: `Proposed` | `Accepted` | `Deprecated` | `Superseded by NNNN` — 이 4개 사이만 전이 가능.

## 5. `harness/GLOSSARY.md` — 용어집

**사전이 아니라 함정 표기 목록**이다. 용어↔코드 명칭이 1:1 로 자명하면 등재하지 않는다.

````markdown
# 용어집

도메인 용어·코드 명칭·한/영 표기의 단일 원천. 사전이 아니라 **함정 표기 목록** —
용어와 코드 명칭이 1:1 로 자명하면 등재하지 않는다.
문서·코드 식별자·커밋 메시지는 본 표의 표기를 따른다.

## 용어 표

| 용어 | 영문 표기 | 코드 명칭 | 정의 | 출처 |
|------|-----------|-----------|------|------|
| (예) 정산 | settlement | `SettlementService` | 판매 대금을 파트너에게 지급하는 절차 | `src/settlement/` |

## 표기 규칙

- 한국어 문서·보고서: "용어" 컬럼 표기 사용
- 코드 식별자·커밋 제목: "영문 표기" 컬럼 사용. 새 식별자 도입 전 본 표를 먼저 확인
- 행은 가나다 순. 코드 명칭은 백틱 필수 (복수 허용), 해당 없는 셀은 `—`

## 금지/주의 표기

| 표준 표기 | 혼용 금지 | 이유 |
|-----------|-----------|------|
| (예) 정산 | 결제 정산, 셀러 정산 | 검색 분열 방지 |
````

**등재 기준**:

| 등재한다 | 등재하지 않는다 |
|----------|-----------------|
| 도메인어↔코드명이 **불일치**하는 매핑 (레거시명, 비자명 축약어 — 예: `PG` = 결제 게이트웨이 모듈), 표기가 2개 이상 존재하는 용어, 한/영 혼용이 실제 발견된 표기, 코드에 없는 도메인 개념어 | 1:1 로 자명한 매핑, 업계 표준 일반 용어 (React, DI 등), 1회성 용어 |

한 줄 판단: **"새 세션 (또는 새 팀원) 이 이 단어만 보고 올바른 파일을 찾아갈 수 있게 되는가?"** — 아니라면 (이미 찾아갈 수 있다면) 등재하지 않는다.

**추가·수정 주체**: 작업 에이전트·사람이 수시 (행 삭제는 사람만), reflect 가 승인 후 append, setup 이 초기 소수 행, audit 은 stale 보고만.

## 6. `harness/LESSONS.md` — 팀 공유 교훈

````markdown
# 교훈 (LESSONS)

팀/기계 간 공유가 필요한 교훈만 기록한다 (개인·머신 로컬 학습은 auto-memory 소관).
**2회 규칙**: 같은 실수가 두 번째 발생했을 때만 등재한다 — 1회성은 노이즈.

## {한 줄 제목} (YYYY-MM-DD)

- 증상: {무엇이 잘못됐나}
- 원인: {근본 원인}
- 규칙: {다음부터 지킬 것}
- 관련: `{코드 명칭}` (해당 시 — 백틱 필수)
````

- "관련" 의 코드 명칭은 audit 의 stale 검사 대상 (코드베이스에서 사라지면 낡은 교훈 후보)
- 낡은 교훈은 잘못된 제약으로 작동한다 — audit 보고 후 사람이 삭제 판단
