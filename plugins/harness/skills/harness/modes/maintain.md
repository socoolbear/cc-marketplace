# Harness — Maintain 모드 (버전 동기화 + 문서 낡음 점검)

설치된 하네스를 플러그인 최신 버전에 맞추고, 문서가 코드·현실과 어긋난 지점을 찾아 보고하는 안전망.
문서 유지의 주체는 작업 에이전트 + 사람이고 (CONTRACTS 원칙 3), maintain 은 놓친 낡음을 주기적으로 잡는다.

> **원칙**: 진단은 읽기 전용. **문서의 본문 데이터 (ADR 항목, GLOSSARY 표 행, LESSONS 항목, 사용자 작성 섹션) 는 어떤 경우에도 보존한다** — maintain 이 만지는 것은 골격과 마커뿐이다.
>
> **사전 지식**: [`../CONTRACTS.md`](../CONTRACTS.md), [`../references/document-formats.md`](../references/document-formats.md) (골격의 정답).

## 워크플로우

### Phase 0: 사전 확인

마커 버전 ≠ 플러그인 버전인 경우에만: **플러그인 자체가 최신인지 확인**한다 (AskUserQuestion). 플러그인이 구버전이면 구버전 기준으로 동기화하게 되므로 의미가 없다 — `/plugin update harness@cc-marketplace` 안내 후 중단하거나, "이미 최신" 확인 후 진행.

버전이 일치하면 이 단계를 건너뛰고 Phase 1 의 낡음 점검만 수행한다.

### Phase 1: 진단 (읽기 전용)

**① 지도 유효성**
- AGENTS.md 의 모든 포인터 (`→ 경로`, 마크다운 링크) 가 실재하는지
- "검증 명령" 의 각 명령이 **실제 실행 가능한지** (dry-run 또는 실행)
- AGENTS.md 가 40줄을 초과했는지

**② 아키텍처 불변 조건 vs 코드**
- enforcement 활성 시 (`scripts/check-layer-import.js` 존재로 감지): 전체 스캔 실행 → 위반 보고. "미판정 N건" 이 보고되면 경로 해석이 잘못됐을 수 있으므로 함께 보고한다
- 공통: `harness/ARCHITECTURE.md` 의 규칙 문장 각각을 코드와 직접 대조 (import 방향·금지 패턴을 Grep 으로 확인) — 문서가 낡았는지 / 코드가 위반인지 **양쪽 가능성을 모두** 보고

**③ ADR.md 정합성**
- 번호 중복·결번, `Superseded by NNNN` 링크가 실재하는 항목을 가리키는지, 오래 방치된 `Proposed` 항목

**④ stale 코드 명칭**
- `harness/GLOSSARY.md` "코드 명칭" 컬럼과 `harness/LESSONS.md` "관련" 필드의 백틱 식별자를 각각 rg → 코드베이스 0 hit 이면 낡은 항목 후보로 보고

**⑤ 골격 diff** (버전 불일치 시 중점, 일치 시에도 훼손 검사)
- **누락된 표준 섹션** → 승인 후 append 대상
- **표준에서 제거된 줄** (구버전 골격의 잔재 — 예: 더 이상 표준이 아닌 경계 항목) → **보고만**. 이미 팀이 의존할 수 있으므로 삭제는 사람 판단
- 본문 데이터·사용자 작성 섹션의 차이는 diff 대상이 아니다

**검사하지 않는 것**: 정의·본문 내용의 정확성 (사람 판단), 문서·커밋 내 표기 위반 전수 검사 (false positive 과다), 미등재 용어 탐지 (기계적 불가).

### Phase 2: 보고 (채팅)

발견을 심각도 (`critical`/`major`/`minor`) 와 함께 채팅으로 보고한다. 로그 파일은 만들지 않는다 (git 이력 + 채팅으로 충분).

### Phase 3: 적용 (승인 후 최소한)

AskUserQuestion 으로 승인받은 항목만 (전체 적용 / 개별 검토 / 건너뛰기):

- **누락 골격 섹션** → 해당 문서에 append. 기존 본문 0 변경
- **깨진 포인터** → 주석 처리 (삭제 X — 사람이 최종 판단)
- **그 외 전부** (규칙-코드 괴리, stale 항목, ADR 정합성, 제거된 줄) → **보고만**. 수정은 사람·작업 에이전트 소관

마무리: `harness/.harness.json` 의 `version` 을 플러그인 버전으로 갱신한다. 단 **사용자가 제안된 변경을 모두 거부한 경우 갱신하지 않는다** (다음 실행에서 다시 제안).

## 적용하지 않는 것

- 플러그인 자체 최신화 → `/plugin update harness@cc-marketplace`
- 코드 수정, `scripts/`·hook 수정 (실행만)
- `docs/legacy-*/`·`_archive/` 정리 (동결·스캔 제외)
