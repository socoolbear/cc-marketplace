# Setup — 최초 구축

하네스가 없는 프로젝트에 지식 문서와 (원하면) 레이어 강제를 한 번 구축한다. 규약·보호 규칙은 [`../SKILL.md`](../SKILL.md), 골격은 [`../references/document-formats.md`](../references/document-formats.md).

## 가드

마커나 `harness/` 문서가 이미 있으면 멈추고 "maintain 으로 점검하세요" 라고 안내한다. 사용자가 재설치를 명시하면 확인을 한 번 더 받고, 기존 `AGENTS.md`·`harness/` 를 `_archive/YYYY-MM-DD-before-reset/` 로 옮긴 뒤 진행한다.

## 1. 분석 (읽기 전용)

필요하면 Explore 서브에이전트로 나눠 조사한다. 수집할 것:

- **검증 명령** — 빌드·테스트·린트·타입체크. 실제로 실행해 존재를 확인한다. 없는 도구는 넣지 않는다.
- **불변 조건 후보** — 레이어와 import 방향, 타입 경계, 금지 패턴. 현황이 아니라 규칙만.
- **기존 결정** — README·docs·커밋에 이미 드러난 아키텍처 결정 (회고 ADR 후보).
- **용어 후보** — 표기 불일치만 (한/영 혼용, 비자명 축약어, 도메인어↔코드명 불일치). 1:1 로 자명한 것은 버린다.
- 기존 AGENTS.md·CLAUDE.md·실패 기록 문서의 존재.

## 2. 문서 생성

골격대로 쓰되 **실재하지 않는 내용은 채우지 않는다** (빈 골격 허용).

| 문서 | 내용 |
|---|---|
| `AGENTS.md` | 검증 명령 / 지식 문서 포인터 4개 / 실재하는 경계 ≤5줄 / 문서 유지 규칙. 기존 파일이 있으면 사용자 섹션을 보존하고 관리 섹션만 재구성한다 |
| `CLAUDE.md` | 없을 때만 `@AGENTS.md` 한 줄. 있으면 손대지 않고, import 가 없다는 사실만 알린다 |
| `harness/ARCHITECTURE.md` | 불변 조건 후보 (규칙 + 이유) |
| `harness/ADR.md` | 골격 + 기존 결정의 회고 항목 (`Accepted`) |
| `harness/GLOSSARY.md` | 골격 + 용어 후보 최대 10행. 행 목록은 사용자 확인 후 기록 |
| `harness/LESSONS.md` | 빈 골격. 기존 실패 기록 문서가 있으면 이관을 제안 |

## 3. 레이어 강제 (선택)

레이어 구조가 있을 때만 "레이어 경계를 코드로 강제할까요? (검사기 + 편집 시 자동 검사 훅 + CI)" 를 한 번 묻는다. 수락하면 [`../references/enforcement.md`](../references/enforcement.md) 대로 만든다:

- 검사기와 훅 어댑터를 **프로젝트의 도구 체인으로** 작성한다 (레이어 표와 DAG 일치).
- 훅은 팀이 공유하는 `.claude/settings.json` 에 등록한다. 먼저 `git check-ignore -q .claude/settings.json` 을 확인한다 — 무시되고 있으면 "이 설정은 커밋되지 않아 팀원에게는 동작하지 않는다" 고 알리고, gitignore 예외 추가 / CI 만 사용 중 사용자가 고르게 한다. 기존 settings 는 병합하고 다른 항목은 건드리지 않는다.
- 검증 명령과 CI 에 검사를 추가하도록 안내한다.

거절하거나 레이어 구조가 없으면 건너뛰고 AGENTS.md 의 레이어 검사 줄도 넣지 않는다.

## 4. 검증 + 마커

- AGENTS.md ≤40줄, 포인터 4개 실재, 검증 명령 실행 가능
- `harness/` 4종이 표준 골격 섹션을 갖춤
- (강제 시) 의도적 위반 파일로 검사기가 실패하고 어댑터가 `additionalContext` JSON 을 내는지 확인 후 원복. 저장소 상위 경로에 소스 디렉토리와 같은 이름이 있어도 거짓 합격이 없는지 확인
- 마지막에 `harness/.harness.json` 을 `{ "version": "<plugin.json version>" }` 으로 만든다

## 하지 않는 것

- 계획·스펙·진행 로그·품질 점수 문서 (원칙 6)
- 기존 문서 대량 재작성 — 이관은 확인 후에만
- `.gitignore`·린트 설정 정비 — 지식 문서 소관이 아니다
