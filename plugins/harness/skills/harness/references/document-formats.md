# 산출 문서 골격 · 등재 기준

setup 이 이 골격으로 만들고, maintain 이 이 골격과 비교한다. **골격을 바꾸면 플러그인 major 를 올린다** ([`../SKILL.md`](../SKILL.md) 버전 규칙).

## 1. `AGENTS.md` — 지도 (≤40줄)

목차이지 백과사전이 아니다. 넘치면 `harness/` 로 내리고 포인터만 남긴다.

````markdown
# {프로젝트명}

{한 줄 설명}

## 검증 명령 (완료 주장 전 반드시 실행)

- 빌드: `{명령}`
- 테스트: `{명령}`
- 린트: `{명령}`
- 타입체크: `{명령}`
- 레이어 검사: `{명령}`   <!-- 강제 활성 시만 -->

## 지식 문서 (필요할 때 읽기)

- 코딩 관례 (코드 쓰기 전 필독) → `{관례 문서 경로}`   <!-- 관례 문서가 있을 때만 -->
- 아키텍처 불변 조건 → `harness/ARCHITECTURE.md`
- 결정 이력 (왜 이렇게 됐나) → `harness/ADR.md`
- 용어집 (도메인 용어·표기) → `harness/GLOSSARY.md`
- 교훈 (반복 실수 방지) → `harness/LESSONS.md`

## 경계

- Never: {실재하는 금지}
- Always: {실재하는 필수}
- Ask first: {확인이 필요한 변경}

## 문서 유지 규칙

- 아키텍처 불변 조건을 바꾸는 변경은 **같은 커밋** 에서 `harness/ARCHITECTURE.md` 갱신 + `harness/ADR.md` 항목 추가
- 작업 중 거짓으로 판명된 문서 문장은 같은 커밋에서 수정
````

- 없는 도구의 검증 명령 줄은 지운다 (빈 자리 표시 금지).
- 경계는 ≤5줄, 프로젝트에 실재하는 것만. 위반 시 사고가 나는 금지·필수·사전 확인 (Never/Always/Ask first) 만 두고, 그 밖의 코딩 관례와 넘친 줄은 관례 문서 (§7) 로 보낸다.
- **관례 포인터** — AGENTS.md 에서 관례 문서를 가리키는 줄 (어느 절에 있든). 관례 문서는 `harness/CONVENTIONS.md` 이거나, 이미 있던 문서 (CONTRIBUTING 등) 중 네이밍·예외 처리·테스트 같은 코딩 관례 절이 실재하는 것이다 (PR 절차·브랜치 규칙만 있으면 아니다).

## 2. `CLAUDE.md` — 연결 파일

없을 때만 `@AGENTS.md` 한 줄로 만든다. Claude Code 의 AGENTS.md 자동 인식은 상위 어디에도 CLAUDE.md 가 없을 때만 동작하므로 연결 파일을 둔다.

## 3. `harness/ARCHITECTURE.md` — 불변 조건

````markdown
# 아키텍처 불변 조건

규칙과 이유만 기록한다. 현황 서술은 쓰지 않는다 (코드가 정답).
불변 조건 변경은 같은 커밋에서 본 파일 갱신 + `ADR.md` 항목 추가.

## 레이어 (허용 import 방향)

| 레이어 | import 가능 | 이유 |
|--------|-------------|------|
| `types` | (없음) | 순수 타입 레이어 유지 |

## 금지 패턴

- {규칙 — 이유}

## 타입 경계

- {규칙 — 이유}
````

레이어 구조가 없으면 실재하는 섹션만 쓴다. 강제가 활성이면 레이어 표와 검사기의 DAG 를 같은 커밋에서 맞춘다.

## 4. `harness/ADR.md` — 결정 이력 (append-only)

````markdown
# 아키텍처 결정 기록 (ADR)

append-only. 발행된 항목의 본문은 수정하지 않는다 (번복은 새 항목으로).
번복: 새 항목 발행 + 기존 항목의 상태 줄만 `Superseded by NNNN` 로 변경.
번호: 4자리 zero-padded, 재사용 금지.
번호는 기본 브랜치에 병합될 때 확정된다. 병합 전 충돌 해소 중 번호가 겹치면 병합하는 쪽 항목을 기본 브랜치 마지막 번호 뒤로 재번호하고, 그 번호를 가리키는 참조도 같은 커밋에서 고친다. 병합 후 발견된 중복은 고치지 않고 보고한다.

## 0001: {결정 제목} — Accepted (YYYY-MM-DD)

### 맥락
### 결정
### 결과
````

- 기록: 레이어 구조, 타입 경계, 핵심 의존성 선택, 금지 패턴, 데이터 정책. 기록하지 않음: 구현 디테일, 쉽게 되돌리는 선택.
- 상태: `Proposed` | `Accepted` | `Deprecated` | `Superseded by NNNN`

## 5. `harness/GLOSSARY.md` — 함정 표기 목록

````markdown
# 용어집

사전이 아니라 **함정 표기 목록** — 용어와 코드 명칭이 1:1 로 자명하면 등재하지 않는다.
문서·코드 식별자·커밋 메시지는 본 표의 표기를 따른다.

## 용어 표

| 용어 | 영문 표기 | 코드 명칭 | 정의 | 출처 |
|------|-----------|-----------|------|------|

## 표기 규칙

- 한국어 문서: "용어" 컬럼 / 코드 식별자·커밋 제목: "영문 표기" 컬럼
- 코드 명칭은 백틱 필수, 해당 없는 셀은 `—`

## 금지/주의 표기

| 표준 표기 | 혼용 금지 | 이유 |
|-----------|-----------|------|
````

**등재 기준** — "새 세션이 이 단어만 보고 올바른 파일을 찾아갈 수 있게 되는가?"

| 등재한다 | 등재하지 않는다 |
|---|---|
| 도메인어↔코드명 불일치 (레거시명, 비자명 축약어), 표기가 둘 이상인 용어, 실제 발견된 한/영 혼용, 코드에 없는 도메인 개념어 | 1:1 로 자명한 매핑, 업계 표준 용어, 1회성 용어 |

## 6. `harness/LESSONS.md` — 팀 공유 교훈

````markdown
# 교훈 (LESSONS)

팀/기계 간 공유가 필요한 교훈만 기록한다 (개인 학습은 auto-memory 소관).
**2회 규칙**: 같은 실수가 서로 다른 날 두 번째 발생했을 때 등재한다. 사용자가 명시적으로 지시한 것은 1회라도 등재한다.

## {한 줄 제목} (YYYY-MM-DD)

- 증상:
- 원인:
- 규칙:
- 관련: `{코드 명칭}`
````

"관련" 의 식별자가 코드에서 사라지면 maintain 이 낡은 교훈 후보로 보고한다 — 낡은 교훈은 잘못된 제약으로 작동한다.

## 7. `harness/CONVENTIONS.md` — 코딩 관례 (선택)

포매터·검사기가 판정할 수 없는, 사람이 정한 코딩 관례 (네이밍·예외 처리·테스트 관례 등) 가 있을 때만 만든다. 이미 관례 문서가 있으면 만들지 않고 AGENTS.md 관례 포인터만 그 파일로 건다 (사본은 갈라진다). 부재는 누락이 아니다.

````markdown
# 코딩 관례 (CONVENTIONS)

코드를 쓰기 전에 읽는다. 포매터·검사기가 판정할 수 없는, 사람이 정한 코딩 관례의 정본이다.
다른 문서 (서브에이전트 정의 포함) 는 여기를 참조만 하고 복사하지 않는다 — 사본은 갈라진다.

## 여기 쓰지 않는 것

| 내용 | 정본 | 강제 |
|------|------|------|
| 포맷·import 순서 | {포매터·린터} | `{명령}` |
| 레이어·import 방향·타입 경계 | `harness/ARCHITECTURE.md` | {검사기 또는 —} |
| 결정 배경 | `harness/ADR.md` | — |
| 용어·식별자 표기 | `harness/GLOSSARY.md` | — |
| 위반 시 사고가 나는 금지·필수·사전 확인 | `AGENTS.md` 경계 (5줄을 넘치면 이 문서의 해당 주제 절) | — |

## {주제}

- {규칙 — 이유}

## 규칙을 추가할 때

1. 린터·검사기로 잡을 수 있으면 그쪽에 넣는다. 문서는 마지막 수단이다
2. 이유를 한 줄로 못 쓰면 아직 규칙이 아니다
3. 위반 예·준수 예를 같이 적는다. 예가 없으면 해석이 갈린다
````

- `## {주제}` 는 프로젝트가 정하는 반복 절이다 — maintain ⑤ 의 골격 비교 대상이 아니다.
- 없는 포매터·검사기 행은 지운다.
