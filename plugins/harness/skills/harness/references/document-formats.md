### 결과

## 이름

멤버 이름에 타입이 이미 말하는 대상을 반복하지 않는다. 서비스·컨트롤러·저장소·클라이언트·도메인 타입 모두 같다 — 타입 이름과 부르는 쪽 변수 이름 (`orderService`) 이 대상을 말한다. 반복하면 읽는 비용만 늘고, 붙인 것·뺀 것이 섞여 이름을 추측할 수 없게 된다.

```
class OrderService {
    create(...)          // 준수 — orderService.create(...)
    get(orderId)
    createOrder(...)     // 위반 — 대상 반복
}
class Order { status }   // orderStatus 는 위반
```

대상 이름을 붙이는 것은 아래 경우뿐이다. 타입 이름 자체는 줄이지 않는다 (import 하면 패키지가 보이지 않는다).

- 타입이 말하지 않는 다른 대상 — `OrderService.listPayments()`. 주 대상과 딸린 대상을 함께 다루면 주 대상만 뺀다 (`get()`·`getLine()`)
- 직렬화되는 이름 — DTO·이벤트·DB 열처럼 계약 (API·이벤트 스키마, DDL) 이 정한 이름
- 프레임워크 등록 이름이 겹칠 때 — 메서드 이름이 등록 키가 되는 프레임워크에서 충돌하는 것만
- 식별자·키 — `orderId`·`orderKey` 는 값의 이름이지 반복이 아니다
- 타입 밖 함수 — 최상위·확장 함수는 감싸는 타입이 없으므로 붙인다. 받는 타입이 대상을 말하면 붙이지 않는다
- 언어 기본 이름과 겹칠 때 — `copy`·`toString`·`equals` 등

## 예외

예외는 잡지 말고 던진다. 대응 (응답 변환·재시도 분류·로그) 은 앱 유형별 전역 처리 한 곳에서 한다. 대응이 흩어지면 같은 오류가 경로마다 다른 응답·재시도·로그를 내고, 삼킨 예외는 장애를 숨긴다.

| 앱 유형 | 전역 처리 한 곳 |
|---|---|
| HTTP | 전역 예외 처리기 (exception handler·resolver) |
| RPC | 서비스 진입점 — 오류 시 허용·거절 판정도 여기서만 |
| 큐·스트림 소비 | 소비 루프 — 일시 오류·하류 장애·독성 메시지 분류와 재시도 판정 |
| 주기·리더 작업 | 작업 실행기 — 한 회차 실패를 기록하고 다음 회차로 |
| 예외로 상태 전이를 표현하는 프레임워크 경계 (워크플로 엔진 등) | 실패 변환 한 곳 — 재시도 가능·불가 실패로 바꾼다 |
| 라이브러리 (SDK) | 공개 진입점 경계 — 라이브러리 예외 타입으로 바꾸는 것이 계약 |

- catch 는 셋만 쓴다: 그 자리에서 흐름이 바뀔 때 (다시 부름·건너뜀·나눠 다시·다른 결과로 바꿈·사유 구분), 프레임워크가 예외로 상태를 바꿀 때 (워크플로 분기), 전역 처리 자신
- 금지: 로그만 찍고 삼키기, 다른 예외로 감싸 다시 던지기만 하기 (전역 처리가 할 일), 같은 대응을 여러 곳에 복사
- 업무 코드는 전송 계층 상태코드를 모른다 — 도메인 예외를 던지고 상태코드 매핑은 전역 처리에서 한다
- 저장소 오류 코드 → 예외 대응표 (재시도 가능 여부 포함) 는 한 곳에만 둔다

```
// 위반 — 삼키고, 업무 코드가 상태코드를 안다
try { repository.save(order) } catch (error) { log(error); return Response(500) }

// 준수 — 던지고, 전역 처리가 상태코드로 바꾼다
repository.save(order)
globalHandler.on(NotFound) -> 404
```

## 변환

업무 함수는 흐름만 쓴다: 조회 (저장소) → 변환 → 판단·계산 (업무 계층) → 쓰기 (저장소). 본문을 넓히는 큰 매핑만 변환기로 뺀다 — 조회·변환이 본문에 섞이면 흐름이 묻히고, 작은 매핑까지 빼면 변환기·입력 타입·시험만 늘어 낭비다.

- **언제 빼는가** — 업무·컨트롤러 본문에서 5줄 이상 (포매터 기준) 차지해 흐름을 가리는 매핑만. 한두 줄 생성자, 목록 감싸기, 같은 한 줄이 여러 곳에 있는 것은 본문에 둔다. 변환기를 만들려고 입력 타입을 새로 만들어야 하는 작은 매핑은 거의 다 본문이다
- **매핑 형태는 둘뿐** — 본문에 쓰거나 변환기. `toResponse`·`from` 같은 별도 매퍼 함수는 두지 않는다
- **대상** — 한 타입을 다른 타입으로 옮겨 담는 매핑 (필드 이름·타입·단위 바꾸기, 기본값 채우기): 업무 객체 조립, 응답 DTO, 메시지 ↔ 도메인, 워크플로 입력·결과. 값을 그대로 묶기, DB 행 매핑, 검증·거부 분기가 있는 파서는 대상이 아니다
- **인터페이스는 하나** — `Transformer<S, T> { transform(source: S): T }`. 부를 때는 {확장 함수가 있는 언어: 단건 `source.transform(XTransformer)`, 여러 건 `items.transform(XTransformer)` — `XTransformer.transform(source)` 로 직접 부르지 않는다. 확장은 import 범위로만, 전역 prototype 패치 금지 / 없는 언어: `XTransformer.transform(source)`}
- 상태가 없으면 싱글턴 (객체·모듈 상수) 으로 만들어 그대로 넘긴다. 설정이 필요한 변환기만 인스턴스로 만들고 생성자로 받는다
- **변환기는 순수하다** — DB·시계·외부 호출·로그·업무 판단 (결과를 가르는 분기, 금액 계산, 상태 판정) 없음. null 이면 칸을 비우는 정도의 모양 분기만. 판단을 넣으면 업무 로직이 "변환" 이름 뒤로 숨는다
- 조회를 모두 마친 뒤 변환한다 — 잠금·트랜잭션 순서가 조회 코드에 그대로 보이게
- 입력이 여럿이면 입력 타입 하나 (`<결과 타입>Source`) 로 묶는다. 조회 결과 묶음은 저장소 쪽, 변환만 변환 쪽
- 이름은 `<결과 타입>Transformer`, 위치는 기능 단위의 `transform` 패키지. DB 없는 단위 시험으로 덮는다

```
// 위반 — 5줄 넘는 매핑과 판단이 흐름 사이에 섞임
row = repository.find(orderId)
input = PricingInput(
    items = row.lines.map { it.sku },
    quantity = row.lines.sumOf { it.count },
    currency = row.currency ?: DEFAULT_CURRENCY,
    status = if (row.total > LIMIT) "BLOCKED" else "OK",   // 판단이 매핑 속에
)

// 준수 — 흐름만
source = repository.findSource(orderId)             // 조회
input = source.transform(PricingInputTransformer)   // 변환 (모양만)
result = Pricing.price(input)                       // 판단·계산
repository.save(result)                             // 쓰기
```

- `## {주제}` 는 프로젝트가 정하는 반복 절이다 — maintain ⑤ 의 골격 비교 대상이 아니다.
- 없는 포매터·검사기 행은 지운다.
- 기본 절은 **제목만 골격이고 본문은 프로젝트 데이터다** — 아래대로 손보거나 팀이 고친 본문을 maintain ⑤ 가 비교하지 않는다 (제목 누락만 본다).
- **기본 절의 전제** — 맞지 않는 절은 지운다: `## 이름` 은 타입·모듈 안에 멤버를 두는 코드, `## 예외` 는 예외로 오류를 전달하는 언어, `## 변환` 은 조회 (저장소) 계층과 업무 계층이 나뉜 코드. 표의 앱 유형은 프로젝트에 있는 행만 남기고, `{…}` 분기는 프로젝트 언어 쪽 하나만 쓴다.
- **ARCHITECTURE 로 가는 줄** — 기본 절을 쓰면 아래 import 금지를 `harness/ARCHITECTURE.md` `## 금지 패턴` 에 프로젝트의 패키지·계층 이름으로 쓴다 (해당 개념이 없으면 쓰지 않는다). 레이어 표 행이 아니므로 레이어 검사기 ([`enforcement.md`](enforcement.md)) 범위 밖이다 — 강제하려면 프로젝트의 아키텍처 테스트 도구 (import 규칙 테스트) 를 쓴다.
  - `## 예외`: 업무 계층은 전송 계층의 상태코드 타입을 import 하지 않는다
  - `## 변환`: `transform` 패키지는 업무 흐름 (서비스)·저장소·설정·DB·프레임워크·시계를 import 하지 않는다 (도메인·입출력 타입은 허용)
