# 산출 문서 골격 · 등재 기준

setup 이 이 골격으로 만들고, maintain 이 이 골격과 비교한다. **골격을 바꾸면 플러그인 major 를 올린다** ([`../SKILL.md`](../SKILL.md) 버전 규칙).

## 1. `AGENTS.md` — 지도 (≤40줄)

목차이지 백과사전이 아니다. 넘치면 `harness/` 로 내리고 포인터만 남긴다.

````markdown
# {프로젝트명}

{한 줄 설명}

## 검증 명령 (완료 주장 전 반드시 실행)

- 빌드: `{명령}`
- 테스트: `{명령}`
- 린트: `{명령}`
- 타입체크: `{명령}`
- 레이어 검사: `{명령}`   <!-- 강제 활성 시만 -->

## 지식 문서 (필요할 때 읽기)

- 아키텍처 불변 조건 → `harness/ARCHITECTURE.md`
- 결정 이력 (왜 이렇게 됐나) → `harness/ADR.md`
- 용어집 (도메인 용어·표기) → `harness/GLOSSARY.md`
- 교훈 (반복 실수 방지) → `harness/LESSONS.md`

## 경계

- Never: {실재하는 금지}
- Always: {실재하는 필수}
- Ask first: {확인이 필요한 변경}

## 문서 유지 규칙

- 아키텍처 불변 조건을 바꾸는 변경은 **같은 커밋** 에서 `harness/ARCHITECTURE.md` 갱신 + `harness/ADR.md` 항목 추가
- 작업 중 거짓으로 판명된 문서 문장은 같은 커밋에서 수정
````

- 없는 도구의 검증 명령 줄은 지운다 (빈 자리 표시 금지).
- 경계는 ≤5줄, 프로젝트에 실재하는 것만.

## 2. `CLAUDE.md` — 연결 파일

없을 때만 `@AGENTS.md` 한 줄로 만든다. Claude Code 의 AGENTS.md 자동 인식은 상위 어디에도 CLAUDE.md 가 없을 때만 동작하므로 연결 파일을 둔다.

## 3. `harness/ARCHITECTURE.md` — 불변 조건

````markdown
# 아키텍처 불변 조건

규칙과 이유만 기록한다. 현황 서술은 쓰지 않는다 (코드가 정답).
불변 조건 변경은 같은 커밋에서 본 파일 갱신 + `ADR.md` 항목 추가.

## 레이어 (허용 import 방향)

| 레이어 | import 가능 | 이유 |
|--------|-------------|------|
| `types` | (없음) | 순수 타입 레이어 유지 |

## 금지 패턴

- {규칙 — 이유}

## 타입 경계

- {규칙 — 이유}
````

레이어 구조가 없으면 실재하는 섹션만 쓴다. 강제가 활성이면 레이어 표와 검사기의 DAG 를 같은 커밋에서 맞춘다.

## 4. `harness/ADR.md` — 결정 이력 (append-only)

````markdown
# 아키텍처 결정 기록 (ADR)

append-only. 발행된 항목의 본문은 수정하지 않는다 (번복은 새 항목으로).
번복: 새 항목 발행 + 기존 항목의 상태 줄만 `Superseded by NNNN` 로 변경.
번호: 4자리 zero-padded, 재사용 금지.

## 0001: {결정 제목} — Accepted (YYYY-MM-DD)

### 맥락
### 결정
### 결과
````

- 기록: 레이어 구조, 타입 경계, 핵심 의존성 선택, 금지 패턴, 데이터 정책. 기록하지 않음: 구현 디테일, 쉽게 되돌리는 선택.
- 상태: `Proposed` | `Accepted` | `Deprecated` | `Superseded by NNNN`

## 5. `harness/GLOSSARY.md` — 함정 표기 목록

````markdown
# 용어집

사전이 아니라 **함정 표기 목록** — 용어와 코드 명칭이 1:1 로 자명하면 등재하지 않는다.
문서·코드 식별자·커밋 메시지는 본 표의 표기를 따른다.

## 용어 표

| 용어 | 영문 표기 | 코드 명칭 | 정의 | 출처 |
|------|-----------|-----------|------|------|

## 표기 규칙

- 한국어 문서: "용어" 컬럼 / 코드 식별자·커밋 제목: "영문 표기" 컬럼
- 코드 명칭은 백틱 필수, 해당 없는 셀은 `—`

## 금지/주의 표기

| 표준 표기 | 혼용 금지 | 이유 |
|-----------|-----------|------|
````

**등재 기준** — "새 세션이 이 단어만 보고 올바른 파일을 찾아갈 수 있게 되는가?"

| 등재한다 | 등재하지 않는다 |
|---|---|
| 도메인어↔코드명 불일치 (레거시명, 비자명 축약어), 표기가 둘 이상인 용어, 실제 발견된 한/영 혼용, 코드에 없는 도메인 개념어 | 1:1 로 자명한 매핑, 업계 표준 용어, 1회성 용어 |

## 6. `harness/LESSONS.md` — 팀 공유 교훈

````markdown
# 교훈 (LESSONS)

팀/기계 간 공유가 필요한 교훈만 기록한다 (개인 학습은 auto-memory 소관).
**2회 규칙**: 같은 실수가 두 번째 발생했을 때만 등재한다.

## {한 줄 제목} (YYYY-MM-DD)

- 증상:
- 원인:
- 규칙:
- 관련: `{코드 명칭}`
````

"관련" 의 식별자가 코드에서 사라지면 maintain 이 낡은 교훈 후보로 보고한다 — 낡은 교훈은 잘못된 제약으로 작동한다.
