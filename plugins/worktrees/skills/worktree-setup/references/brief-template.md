# BRIEF.md 템플릿

`<우산루트>/.worktrees/<작업명>/BRIEF.md` 에 이 골격으로 쓴다. **해당 없는 절은 통째로 뺀다** — 빈 절을 자리 채우기로 남기지 않는다. 다만 `## 미확인` 은 조사를 했다면 거의 항상 남을 것이 있다.

분량 기준: A4 한 장. 넘어가면 요약이 아니라 사본이 되고 있는 것이니, 원문 링크에 맡기고 줄인다.

```markdown
# <작업명> — 작업 시작 브리핑

<한두 문장. 무엇이 문제고 이 작업으로 무엇을 바꾸는가.>

출처: <슬랙 쓰레드 permalink> · <이슈 트래커 티켓> · <관련 문서>

## 작업 공간

| 디렉토리 | repo | 브랜치 | 기준 |
|---|---|---|---|
| `<dir>` | `<repo>` (<모노레포면 앱 경로>) | `<브랜치명>` | origin/main `<단축해시>` |

의존성 미설치. 빌드·테스트 전에 `<repo별 설치 명령>` 필요.

## 무엇이 문제인가

<코드로 확인한 사실만. 각 줄에 `파일:라인` 을 단다. 추측은 여기 쓰지 않는다.>

- `<파일:라인>` — <확인한 동작>
- `<파일:라인>` — <확인한 동작>

## 결정된 것

- <누가 무엇을 정했는지. 정한 사람을 남긴다 — 나중에 되물을 자리가 된다.>

## 아직 열린 쟁점

<첫 커밋의 방향을 바꾸는 것만. 각 항목에 선택지와 (있다면) 근거 있는 의견을 붙인다.>

1. **<쟁점>** — <선택지 A> vs <선택지 B>. <어느 쪽이 왜 나은지, 또는 누가 정해야 하는지.>

## 깨지면 안 되는 것

<이 변경으로 회귀할 수 있는 기존 동작. 근거 파일을 단다.>

- <동작> — <왜 깨지는지> (`<파일:라인>`)

## 미확인

<근거를 못 잡고 남긴 것. "확인함" 과 섞이면 브리핑 전체의 신뢰가 떨어진다.>

- <무엇을 확인 못 했는지> — <무엇을 보면 확정되는지>

## 시작 지점

<다음 세션이 첫 삽을 어디에 뜰지. 파일 경로와 명령까지.>
```

## 절별 판단 기준

| 절 | 넣을 것 | 빼야 할 것 |
|---|---|---|
| 무엇이 문제인가 | 파일을 열어 확인한 동작 | 이름·주석·에러 문구로 짐작한 동작 |
| 결정된 것 | 사람이 명시적으로 답한 것 | "그렇게 하기로 한 분위기" |
| 아직 열린 쟁점 | 코드 방향이 갈리는 것 | 나중에 정해도 되는 세부 |
| 깨지면 안 되는 것 | 근거 파일이 있는 회귀 위험 | 일반론적 주의사항 |
| 미확인 | 확인 못 한 채 전제로 깔린 것 | 애초에 범위 밖인 것 |
