# catchup — 이전 세션 이어받기

이전 세션의 transcript(`~/.claude/projects/<프로젝트>/<세션ID>.jsonl`)를 요약해
현재 세션으로 가져온다. 디스크에 파일을 남기지 않는다.

핵심 판단 두 가지만 이 스킬이 정한다:
**(1) 어느 세션을 이어받을 것인가, (2) 요약을 어떤 형태로 전달할 것인가.**
나머지는 번들 스크립트가 처리한다.

## 1. 후보 세션 나열

```bash
python3 <스킬경로>/scripts/list_sessions.py
```

- 현재 프로젝트의 세션을 최근 활동순으로 JSON Lines 로 출력한다 (현재 세션은 자동 제외).
- 세션 이름·마지막 활동·git 브랜치·메시지 수·첫/마지막 프롬프트가 담긴다.
- exit 2 (후보 없음) 이면: 그 사실을 보고하고, `.prompts/HANDOFF.md` 가 있으면 그걸 대신 읽는다.
  transcript 는 이 머신에만 있고 기본 30일 뒤 정리되므로, 오래된 작업은 후보에 없을 수 있다.

## 2. 대상 세션 선정

**인자가 있으면** 그걸 우선한다. 세션 ID 앞자리 → `id` 매칭.
그 외 문자열은 공백으로 나눈 키워드들로 `name` · `first_prompt` · `last_prompt` 를
부분 매칭한다. 한국어 띄어쓰기 변형("결제수단" vs "결제 수단")을 놓치지 않도록
**양쪽 다 공백을 제거한 뒤** 비교하고, 키워드 일부만 맞아도 후보로 친다.
유일하게 특정되면 진행, 여러 개면 AskUserQuestion 으로 매칭된 것들을 제시,
0개면 후보 목록을 보여주고 사용자에게 묻는다.

**인자가 없으면** "가장 최근" 이 아니라 **작업 연속 가능성이 가장 높은 세션**을 고른다.
판단 신호, 우선순위 순:

1. **사용자 힌트** — 현재 세션에서 사용자가 언급한 주제와 첫/마지막 프롬프트가 닿는 세션.
   이전 세션이 "다음 세션은 X 에서 연다" 로 끝났고 현재 작업 디렉터리가 X 면 가장 강한 신호다
2. **실질 작업량** — `assistant_msgs` 가 한 자리 수인 세션(질문 한 번, 즉시 종료)은
   최근이어도 이어받을 내용이 없다. 실질 세션을 우선한다
3. **브랜치 일치** — 현재 git 브랜치와 `branch` 가 같은 세션. 단, 여러 repo 를 담는
   작업 루트처럼 cwd 가 git 저장소가 아니면 `branch` 가 전부 "HEAD" 라 무의미하다 — 건너뛴다
4. **최근성** — 위 신호로 안 갈리면 최근 세션. 1위가 2위보다 **하루 이상** 최근이면
   그대로 진행하고, 그보다 붙어 있으면 추측하지 말고 AskUserQuestion 으로 상위 2~3개를
   제시한다 (라벨: 세션 이름 또는 첫 프롬프트 요약 + 마지막 활동 시각)

## 3. 요약 — 서브에이전트에 위임

transcript 는 수백 KB~수 MB 라 직접 읽으면 현재 컨텍스트가 오염된다.
반드시 변환 → 위임 순서로 한다:

```bash
python3 <스킬경로>/scripts/extract_transcript.py <transcript.jsonl> --out <scratchpad>/catchup.md
```

그 다음 `Explore` 서브에이전트 (`model: sonnet`) 를 스폰해 `<scratchpad>/catchup.md` 를
읽고 아래 형식으로 요약하게 한다. 파일이 크면 **뒷부분(최종 상태)을 먼저** 읽고
앞부분은 목표 파악에 필요한 만큼만 읽으라고 지시한다. 대화록에 `[이전 요약]` 섹션이
있으면 그 이전 내용의 압축본이므로 함께 반영하게 한다.

서브에이전트가 돌려줄 형식 (해당 없는 섹션은 빼게 한다):

```markdown
# [작업 제목] 이어받기 (마지막 활동: YYYY-MM-DD HH:MM, 브랜치: xxx)

## 작업 개요
[목적과 범위 1-2문장]

## 완료된 작업
- [x] ...

## 남은 작업
- [ ] ...

## 핵심 참조 파일
- `경로`: 역할

## 결정 사항·주의점
- [세션 중 내린 결정과 이유, 막혔던 지점, 사용자가 준 제약]

## 마지막 상황
[세션이 어디서 왜 끝났는지 — 다음 행동을 정하는 데 필요한 직전 맥락]
```

## 4. 현재 상태와 대조 후 보고

transcript 는 과거 시점의 기록이다. 요약을 받으면 `git status` · `git log --oneline -5` 로
현재 상태와 대조한다 — "남은 작업" 이 그 사이 커밋됐거나 파일이 사라졌을 수 있다.
cwd 가 git 저장소가 아니면(여러 repo 를 담는 작업 루트) 요약의 "핵심 참조 파일" 에 나온
repo · worktree 각각에서 대조한다.

최종 보고는 위 요약 + 대조 결과(어긋난 항목만) + "다음으로 할 일" 제안 한 줄.
보고 후에는 사용자 지시를 기다린다 — 남은 작업을 임의로 시작하지 않는다.
