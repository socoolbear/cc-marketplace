# 로컬 파일 — 드문 규칙과 태그 대응

`link`·`migrate` 가 내는 태그의 뜻과 대응. 본문 규칙(SKILL.md 2-1·2-2 절)에 없는 드문 상황만 여기 담는다.

## 태그 대응표

| 태그 | 뜻 | 대응 |
|---|---|---|
| `[tracked]` | `migrate` 의 `<rel-path>` 가 체크아웃에서 git 추적 파일(또는 추적 파일을 포함한 디렉토리)이다 | 복사하지 않는다. 이유: worktree 에 같은 경로의 추적 파일이 있어 `link` 가 영원히 `[exists]` 로 건너뛰고 `.local/` 에 쓸모없는 사본만 남는다. 플래그로 우회할 수 없다 |
| `[not-ignored]` | `migrate` 의 `<rel-path>` 가 `.gitignore` 대상이 아니다 | 경고만 하고 그대로 복사를 진행한다 |
| `[exists]` | `link`: worktree 의 같은 경로에 이미 실파일·실디렉토리나 다른 곳을 가리키는 심링크가 있다. `migrate`: `.local/<repo>/<rel-path>` 에 이미 사본이 있다 | 어느 쪽이든 건너뛴다 (`migrate` 는 재실행을 "이미 됐음"으로 보고 종료코드에도 안 잡는다). 갱신하려면 `diff -rq <checkout>/<rel> <root>/.local/<repo>/<rel>` 로 다른지만 확인한 뒤, 지우고 다시 실행할지는 사용자가 정한다 |
| `[missing]` | `migrate` 의 소스 경로(`<checkout-path>/<rel-path>`)가 없다 | 건너뛴다 |
| `[bad-path]` | `<rel-path>` 가 절대경로이거나 `..` 를 포함하거나 비어 있다 | 거부한다 |
| `[symlink]` | `migrate` 의 소스가 **상대** 심링크다 (절대 심링크는 같은 대상으로 다시 `ln -s` 해 정상 처리된다) | 건너뛴다. 원본 위치를 사용자가 직접 지정해야 한다 |
| `[copy-failed]` | 복사(`cp -pR`) 가 실패했다 (읽기 불가 파일 등. 소켓은 `cp` 가 조용히 건너뛰므로 실패가 아니다) | 부분 사본을 되돌리고 실패로 처리한다. 원인을 없앤 뒤 재실행하면 다시 시도된다 |
| `[dangling]` | 복사한 디렉토리 안에, 원본 체크아웃 밖을 가리키던 상대 심링크가 끊긴 채로 N 개 들어 있다 | 경고만 한다 (개수만). 어떤 링크인지는 `find <root>/.local/<repo>/<rel> -type l ! -exec test -e {} \; -print` 로 본다 |
| `[remote]` | 체크아웃의 origin 과 bare 저장소의 origin 이 문자열로 다르다 (ssh alias·https·`.git` 유무는 정규화하지 않는다) | 경고만 하고 진행한다 |
| `[bad-name]` | `link` 대상 이름에 `# ! [ ] * ? \` 같은 문자나 앞뒤 공백이 있다 | 경고 후 건너뛴다. `info/exclude` 패턴에 못 쓰는 이름이라서다 |

## 태스크 전용 값

worktree 의 그 자리에 실파일을 두면 `link` 가 `[exists]` 로 건너뛰어 태스크 전용 값을 지킨다 (`worktree-setup` 4절과 같은 원칙). 단, **연결 단위는 링크 하나**다 — 디렉토리를 통째로 심링크한 경우, 그 안에 쓴 파일은 실제로는 `.local/` 쪽에 쓰인 것이라 전 태스크에 전파된다. 디렉토리 안 일부만 태스크 전용으로 두려면 그 디렉토리 링크를 지우고 실디렉토리를 만든 뒤 `link` 를 재실행한다 (나머지 항목은 파일 단위로 다시 연결된다).

## 도구가 덮어쓰는 설정 파일

IDE·세션 설정처럼 도구가 통째로 다시 쓰는 파일은, 도구가 "임시 파일 작성 후 rename" 으로 저장하면 심링크가 실파일로 바뀌어 `.local/` 과의 연결이 끊긴다. 끊긴 파일은 `done` 의 `[untracked]` 목록에 나타나므로 그때 알아차릴 수 있다 — `.local/` 쪽을 최신으로 맞출지는 사용자가 정한다.

## `.local/` 은 머신 로컬이다

`.local/` 은 워크스페이스 repo 에 추적되지 않고 다른 머신으로 옮겨지지 않는다. 새 머신에서는 `add` (인자 없이) 로 `repos.txt` 의 bare 저장소만 복원되고, `.local/` 은 각자 다시 채워야 한다.

## `.local/` 이 원본이다

심링크는 `.local/<repo>/` 를 가리키므로, **`.local/` 쪽이 유일한 원본**이다. 워크스페이스 루트를 지우면 `.local/` 도 함께 사라져 비밀 파일 원본이 사라진다. 백업 범위에 `.local/` 을 포함해야 한다.

## `.local/` 에서 항목을 뺄 때

`link` 는 디렉토리가 실디렉토리로 바뀌는 경우(예: sync 로 추적 파일이 생긴 경로)에는 `<bare>/info/exclude` 의 해당 줄을 자동으로 지운다. 하지만 사용자가 `.local/` 에서 항목을 통째로 빼는 경우엔 이 정리를 자동으로 하지 않는다 — `<bare>/info/exclude` 에서 그 줄을 수동으로 지운다.

## 1.1.0 이전 태스크

1.1.0 이전에 `new` 로 만든 태스크의 파일 단위 링크는 그대로 유지된다. 디렉토리 단위로 승격하지 않는다.

## 기존 워크스페이스의 `.gitignore` 갱신

`shared/` 등 새 ignore 줄이 필요하면 `init <root>` 를 재실행한다 (멱등이라 안전하다).

## 기존 체크아웃을 정리(삭제)하기 전에

`migrate` 는 복사만 하고 기존 체크아웃을 지우지 않는다. 정리는 사용자 몫이며, 지우기 전에 다음을 확인한다.

- 미push 커밋이 없는지 (`git -C <checkout> log --branches --not --remotes --oneline`)
- stash 가 남아 있지 않은지 (`git -C <checkout> stash list`)
- `git -C <checkout> status --ignored --short` 에 `!!`(ignored)·`??`(untracked) 로 남은, 아직 가져오지 않은 파일이 없는지
