# requires.txt — 요구 선언

워크스페이스 repo 가 "여기서 일하는 장비에 있어야 하는 것" 을 적어 두는 파일이다. 세션 시작 훅 (`check`) 이 필수 항목 중 빠진 것을 알리고, `requires` 명령이 전체를 표로 보여 준다. 둘 다 읽기만 한다 — 설치·등록은 안내만 한다.

## 형식

한 줄에 하나. `#` 으로 시작하는 줄과 빈 줄은 무시한다. 앞 200줄만 읽고, 1000자를 넘는 줄은 알 수 없는 줄로 본다.

```
# plugin <이름>@<마켓플레이스> [<최소 버전>] [optional]
plugin some-guard@some-marketplace 1.2.0
plugin some-loop@some-marketplace optional

# path <경로> [optional] [-- <없을 때 보여 줄 안내>]
path ~/.config/tool/rules -- mkdir -p ~/.config/tool && ln -sfn "{dir}/policy/rules" ~/.config/tool/rules
path ~/.config/some-loop/env optional -- 세션에서 /some-loop:setup
```

| 줄 | 충족 조건 | 규칙 |
|---|---|---|
| `plugin` | 설치 기록 (`<설정 폴더>/plugins/installed_plugins.json`) 에 있고, 최소 버전을 적었으면 그 이상 | 이름은 `이름@마켓플레이스` (영문·숫자·`.`·`_`·`-`, 첫 글자는 영문·숫자). 버전은 숫자와 `.` (`1.2.0`, 앞의 `v` 허용) — `1.10.0 > 1.9.0`, `2.0 = 2.0.0` |
| `path` | 그 경로가 있음 (끊긴 심링크는 없는 것) | `/` · `~/` · `$HOME/` 로 시작, 공백 없음, 200자까지. 안내문의 `{dir}` 은 이 파일이 있는 폴더의 절대 경로로 바뀐다 |

형식에 맞지 않는 줄은 세션 시작 때 무시되고 `requires` 에 `알 수 없는 줄` 로 나온다.

**안내문은 그대로 실행하면 그 경로가 생기는 명령으로 적는다.** 상위 폴더가 없는 새 장비와 끊긴 심링크가 남은 장비에서도 통해야 한다 (`mkdir -p … && ln -sfn …`). 안내된 명령으로 없앨 수 없는 안내는 세션마다 다시 뜬다. `{dir}` 을 바꾼 뒤 300자를 넘는 안내문은 통째로 생략된다.

선언 파일의 글은 셸로 평가되지 않는다 — `~/` · `$HOME/` · `{dir}` 치환 말고는 글자 그대로 다룬다.

## 필수와 optional

- **필수** (표시 없음): 빠져 있으면 워크스페이스 안에서 새 세션을 열 때마다 알린다. **이 워크스페이스에서 일하는 모든 장비에 필요하고, 안내된 명령으로 바로 갖출 수 있는 것만** 적는다. 아직 배포되지 않은 플러그인을 필수로 적으면 그날부터 모든 세션에 안내가 뜬다
- **`optional`**: 세션 시작 때 알리지 않고 `requires` 에만 나온다. 한 장비에서만 켜는 장치와 그 장비 등록에 쓴다

`path` 줄로 볼 수 있는 것은 "그 경로가 있는가" 뿐이다. 장비 등록의 증거가 경로 하나로 드러나면 (`설정 파일`, `심링크`) 선언하고, 그렇지 않은 등록 (어떤 파일 안의 한 줄 등) 은 그 플러그인이 스스로 알리게 둔다.

## 위치

taskspace 루트에서 시작해 **그 루트가 속한 git repo 의 꼭대기까지** 올라가며 처음 만난 `requires.txt` 하나만 읽는다. 세션을 태스크 루트 · worktree · 워크스페이스 루트 어디서 열어도 같은 파일이다.

- 워크스페이스 하나가 곧 git repo 면 루트에 둔다
- 여러 워크스페이스를 묶는 상위 repo 면 꼭대기 한 곳에 둔다 — 아래 워크스페이스가 함께 쓴다
- 어떤 워크스페이스만 다르게 하려면 그 루트에 따로 둔다. **합치지 않으므로** 그 파일이 꼭대기 선언을 통째로 대신한다 (빈 파일을 두면 그 워크스페이스는 요구 점검을 하지 않는다)
- 루트가 git repo 안이 아니면 루트의 파일만 본다

## 장비에서 끄기

환경 변수 `TASKSPACE_REQUIRES_SKIP` 에 뺄 대상을 공백 (또는 탭·줄바꿈) 으로 나눠 적는다. 대상은 선언 파일에 적힌 글자 그대로다 (`some-guard@some-marketplace`, `~/.config/tool/rules`). `all` 이면 요구 점검 전체를 끈다. 뺀 대상은 `requires` 에 `건너뜀` 으로 나온다.

쓰는 경우: 플러그인을 설치하지 않고 로컬 폴더에서 직접 불러 쓰는 개발 장비 (설치 기록에 없어 미설치로 보인다), 그 장치를 일부러 쓰지 않는 장비.

## 알아 둘 한계

- 세션 시작 점검은 설치 기록만 본다. **설치됐지만 꺼진 플러그인** 은 `requires` 에서만 `꺼짐` 으로 보인다 (`claude plugin list` 에 묻는다)
- `jq` 가 없거나 설치 기록을 읽을 수 없으면 세션 시작 점검은 `plugin` 줄을 조용히 건너뛴다 (`path` 줄은 본다). `requires` 는 `판정 불가` 와 이유를 표시한다
- taskspace 플러그인이 없는 장비에서는 이 점검 자체가 돌지 않는다. 새 장비 절차의 첫 단계 (마켓플레이스 등록 · taskspace 설치) 는 워크스페이스의 문서에 따로 적어 둔다
