type: llm
criteria: "DB 지연, 느린 단말, 비정상 프레임이 발생해도 서버 메모리 사용량이 상한 안에 머물도록 설계하는가?"
---
통과: 세 경로의 상한을 모두 제시한다. (1) DB 가 느려지면 유한한 업링크 큐가 차고 소켓 읽기 중단 또는 거절로 단말 쪽에 압력을 전달한다. (2) 단말별 송신 큐에 상한을 두고 초과하면 연결 종료나 정해진 폐기로 처리한다. (3) 프레임 길이 필드를 믿고 할당하지 않고 최대 길이를 넘으면 메모리를 할당하기 전에 거부한다. 실패: 세 경로 중 하나라도 상한이 없거나, 무제한 큐·버퍼로 흡수하거나, 오토스케일링·메모리 증설만으로 대응한다.
