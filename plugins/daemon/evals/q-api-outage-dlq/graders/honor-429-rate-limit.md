---
type: llm
criteria: "429 에 대해 Retry-After 를 존중하고 지수 백오프·jitter 와 전체 소비자 기준 송신 속도 제한으로 대응하는가?"
---
통과: 429·503 응답의 `Retry-After` 헤더(RFC 9110) 가 있으면 그만큼 기다리고, 없으면 상한 있는 지수 백오프 + jitter 를 쓰며, 토큰 버킷·동시성 제한 등으로 송신 속도를 파트너 한도 아래로 맞춘다 — 소비자 인스턴스·파티션 수만큼 병렬도가 늘어난다는 점(전역 또는 인스턴스별 몫 계산) 을 다루면 더 좋다. 실패: 429 를 일반 오류처럼 즉시·고정 간격으로 3번 재시도하고 DLQ 로 보내거나, 장애 복구 직후 쌓인 백로그를 제한 없이 쏟아내 다시 429·장애를 유발하는 설계.
