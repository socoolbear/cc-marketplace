# 적대적 검증

자기가 만든 변경을 스스로 검토하면 감싸는 편향이 남는다. 라운드마다 **새 리뷰어** (general-purpose 서브에이전트) 를 띄운다.

## 라운드 규칙

- 변경 파일 3개 이상·구조적 결정·되돌리기 어려움 중 하나에 해당하면 수행한다. 아니면 생략하고 이유를 한 줄 남긴다.
- BLOCKER 가 0건인 라운드가 나오면 멈춘다. 최대 5라운드.
- MINOR 는 반영하거나, 기각 이유를 결정 기록에 남긴다.
- 리뷰어의 **사실 주장** ("명령을 실행하지 않았다", "이 필드는 갱신되지 않는다") 은 반영 전에 직접 확인한다. 틀린 주장도 섞여 나온다.
- 같은 지점이 두 라운드 연속 뒤집히면 멈추고 사용자에게 결정을 받는다 (확정 결정이 리뷰어에게 전달되지 않았다는 신호다).
- 판정 표·diff 는 라운드마다 scratchpad 에 새로 저장해 경로로 넘긴다.

- 요청 해석: 범위를 임의로 넓히거나 좁힌 곳

- 모순: 문서 간, 문서와 코드 간
- 회귀: 깨지는 기존 동작, 빠진 경우
- 검증 허점: 이 검증으로 증명되지 않는 것
