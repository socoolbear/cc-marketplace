# Evolve

플러그인은 한 번 만들고 끝나지 않는다. 공식 기능이 나오면 필요 없어지고, 모델이 나아지면 지시가 군더더기가 되고, 새 자료가 나오면 고칠 곳이 보인다. 이 스킬은 그 반복 작업의 공통 뼈대다.

| 파일 | 역할 |
|---|---|
| [`references/sources.md`](references/sources.md) | 외부 신호를 어디서 어떻게 확인하나 (3단계·sweep) |
| [`references/review.md`](references/review.md) | 적대적 검증 리뷰어 프롬프트 틀·라운드 규칙 (5·7단계) |
| [`references/deprecation.md`](references/deprecation.md) | deprecate·삭제 절차 |
| `docs/evolution/<플러그인>.md` | 결정 기록 — 산출물. 시작 전에 읽고 끝에 갱신한다 |

## 원칙

1. **근거 없는 판정 금지** — 판정마다 출처 (문서 링크·커밋·세션 도구·memory·eval 결과) 를 단다. "새로우니까" 는 근거가 아니다.
2. **결정 기록이 먼저** — 이미 채택·기각·보류한 판정은 재검토 조건이 충족됐을 때만 다시 다룬다. 확정된 결정을 리뷰어가 뒤집게 두지 않는다.
3. **줄이는 쪽을 먼저 본다** — 반영보다 제거·정리 후보를 먼저 찾는다. 모델이 나아질수록 스킬은 짧아져야 한다.
4. **repo 규칙 그대로** — `AGENTS.md` 의 버전 bump·생성 파일 표·실경로 금지·삭제 전 확인을 따른다.

## 판정

| 판정 | 뜻 |
|---|---|
| 반영 | 새 근거가 개선을 요구한다 |
| 제거 | 더는 필요 없는 규칙·문구 (모델이 기본으로 하는 것 포함) |
| 정리 | 중복·비대·흩어진 서술을 합친다 |
| 모순 해결 | 문서끼리, 문서와 코드가 어긋난다 |
| deprecate | 공식 기능이 대체한다 → [`references/deprecation.md`](references/deprecation.md) |
| 보류 | 지금은 하지 않는다. **재검토 조건** 을 반드시 적는다 |

## 결정 기록

`docs/evolution/<플러그인>.md` 하나에 진화 회차를 최신이 위로 쌓는다.

```markdown
## YYYY-MM-DD — <한 줄 주제> (<버전>)

자료: <이번에 본 외부 자료>

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
```

기각·보류도 적는다 — 적지 않으면 다음 회차가 같은 논의를 반복한다. 재검토 조건은 확인 가능한 사건으로 쓴다 ("공식 출시되면", "다음 major 때"). 이 파일은 커밋되므로 근거에 다른 프로젝트 이름·실제 경로를 옮겨 적지 않는다 (memory 근거는 내용만 요약).

## 분기

- 플러그인 이름이나 자료가 주어졌으면 **evolve**
- "전체"·"점검"·"sweep" 이거나 정기 루틴 실행이면 **sweep**
- 모호하면 묻는다 (무인 실행이면 sweep)

## evolve — 플러그인 하나를 깊게

1. **대상 고정** — `plugins/<n>/` 전체, marketplace 항목, `docs/evolution/<n>.md`. 생성 파일 표에 걸리는 파일은 원본 repo 에서 고치도록 안내하고 손대지 않는다.
2. **기준선** — 플러그인이 약속하는 동작 (description·원칙·모드), 최근 커밋 (`git log -- plugins/<n>`), eval 유무. 결정 기록의 보류 건과 재검토 조건.
3. **신호 수집** — [`references/sources.md`](references/sources.md). 자료가 많으면 서브에이전트로 나눠 병렬 수집한다.
4. **판정** — 신호마다 판정 하나 + 근거. 제거·정리 후보를 먼저 적는다.
5. **설계 검증·승인** — 판정 표를 [`references/review.md`](references/review.md) 로 먼저 검증한 뒤 (실행 전 설계 오류 잡기), 보여 주고 AskUserQuestion 으로 고르게 한다. 승인 전에는 쓰지 않는다. 사용자가 확정한 결정은 이유와 함께 목록으로 정리해 7단계에 넘긴다.
6. **구현** — 승인된 것만. 파일은 Edit 으로 고친다 (스크립트로 파일을 통째 다시 쓰다 비운 사고가 있었다).
7. **구현 검증** — 같은 절차로 diff 를 검증한다. 설계 검증이 못 잡는 구현 버그 (판정 기준과 코드의 어긋남, 반복 조건 등) 가 여기서 나온다.
8. **마무리**
   - repo 검증 명령 (`AGENTS.md`) + 플러그인 테스트. 동작을 바꿨으면 eval 을 추가하거나 추가하지 않는 이유를 결정 기록에 남긴다
   - 산출물에 영향이 있으면 `plugin.json`·`marketplace.json` 버전을 함께 올린다. 플러그인에 changelog 가 있으면 항목을 추가한다
   - `docs/evolution/<n>.md` 에 이번 판정 (채택·기각·보류 + 재검토 조건) 을 추가한다
   - 커밋한다. push 는 요청받을 때만

## sweep — 전체를 얕게

플러그인마다 아래를 훑고 **후보만** 보고한다. 파일은 쓰지 않는다. 얕은 clone (`git rev-parse --is-shallow-repository` 가 `true`) 이면 먼저 `git fetch --unshallow` 하고, 안 되면 커밋 날짜를 쓰는 점검은 확인 불가로 적는다.

| 점검 | 후보 판정 |
|---|---|
| 공식 기능과 겹치는가 ([`references/sources.md`](references/sources.md) 공식 기능). 결정 기록에 같은 항목이 기각·보류로 있으면 제외 | deprecate |
| 결정 기록의 보류 건 중 재검토 조건이 충족됐는가 | 그 보류 건 |
| 결정 기록이 있는 플러그인에서, 마지막 회차 이후 동작을 바꾼 커밋이 있는데 eval 이 없고 기록에 생략 사유도 없는가 (기록이 없으면 이 점검은 건너뛴다) | 반영 (eval) |
| 마지막 커밋 (`git log -1 --format=%cs -- plugins/<n> docs/evolution/<n>.md` — 기각만 하고 끝난 회차도 기준이 되도록 기록 파일 포함) 이후 Claude Code CHANGELOG 에 추가된 줄 중 플러그인·스킬·명령 이름이 들어간 줄이 있는가. CHANGELOG 에는 날짜가 없으므로 기간은 커밋 이력으로 구한다 (`gh api 'repos/anthropics/claude-code/commits?path=CHANGELOG.md&until=<날짜>&per_page=1'` 로 그 시점 직전 커밋을 구해 현재와 diff). `gh` 가 없으면 확인 불가. 이름이 일반 단어 (`resume`·`extract`·`sessions` 등) 면 줄을 읽고 실제로 관련 있을 때만 올린다 | evolve 권장 |
| repo 검증 명령 실패 (JSON·버전 일치·링크) | 모순 해결 |

보고는 위 표의 순서 (deprecate → 보류 재검토 → eval → CHANGELOG → 검증 실패) 로 상위 5건을 표로: `플러그인 | 후보 판정 | 근거 | 다음 행동 (evolve <n>)`. 후보가 없으면 "후보 없음" 한 줄.

**무인 실행** (정기 루틴) 이면 질문하지 않는다. 실행 프롬프트가 보고 채널을 지정하면 그곳으로, 지정이 없으면 최종 응답 본문이 보고다. "후보 없음" 도 반드시 보고한다 (루틴이 돌았다는 확인). 세션 도구 목록·auto-memory 처럼 그 환경에서 볼 수 없는 신호는 "확인 불가" 로 적는다.

## 하지 않는 것

- 플러그인 삭제·마켓플레이스 이름 변경을 묻지 않고 하기
- sweep 에서 파일 쓰기
- 새 플러그인 만들기 — `skill-creator` 를 안내한다
