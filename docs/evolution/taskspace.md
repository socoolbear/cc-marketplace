## 2026-11-20 — 워크스페이스가 필요한 플러그인·경로를 선언하고 세션 시작 때 점검 (2.12.0)

자료: 사용자 요청 — 작업 장치를 플러그인으로 옮기면서, 설정 저장소를 깔지 않은 장비에서도 워크스페이스를 clone 하고 세션을 열면 무엇을 설치·등록해야 하는지 안내되게. 확인한 사실: 상위 폴더의 프로젝트 설정은 하위 폴더 세션에 실리지 않아 워크스페이스가 플러그인을 직접 켤 수 없다 (실측). 설치 기록 파일과 `claude plugin list --json` 의 형태 (이 장비에서 확인).

| 기각 | 훅이 상태 파일로 안내 횟수를 줄이기 | 세션 시작만으로 파일이 바뀌면 원인을 찾기 어렵다 (2.10.0 의 원칙) | — |

## 2026-11-18 — 워크스페이스 repo 커밋·push 를 묻지 않고 함 (2.11.0)

자료: 사용자 지적 — 워크스페이스 커밋·push 를 매번 승인해 줘야 했다. 세션 보고에 "이 repo 는 지시가 있을 때만 커밋하는 규칙이라 남겼습니다" 가 반복됐고, 워크스페이스에는 끝난 태스크의 archive 이동·INDEX.md 갱신이 미커밋으로 쌓여 있었다.

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
| 모순 해결 | "워크스페이스 repo 의 commit·push 는 지시할 때만" 을 "묻지 않고 한다" 로 (SKILL.md 8절, `tasks/CLAUDE.md` 템플릿, task-intake) | 기록만 담는 repo 라 배포가 없고 되돌리기 쉽다. 지시를 기다리는 동안 다른 장비에서 notes 가 보이지 않는다 (사용자 요청) | 워크스페이스 repo 에 배포·검사 workflow 를 거는 사용 사례가 생기면 |
| 반영 | 커밋 시점 (상태 변경 직후 · 보고 직전 · 세션 닫기 전) 과 경로 지정 커밋 | 한 체크아웃을 여러 세션이 함께 쓰므로 경로 없는 `git add -A` 는 다른 세션의 쓰던 notes 를 섞는다 | 세션별 커밋이 자주 충돌하면 |
| 유지 | `init` 의 첫 커밋과 원격 연결은 사용자 몫 | 어느 원격에 올릴지는 스킬이 정할 수 없다 | — |
| 유지 | 코드 repo 의 수정·커밋·PR 은 지시할 때만 | 이 스킬의 범위는 작업 공간 관리다. 코드 repo 규칙은 그 repo 와 사용자 전역 규칙이 정한다 | — |
| 기록 | eval·적대적 검증 생략 | 스크립트 동작은 바뀌지 않고 문서 문장만 바뀌었다. `upgrade` 가 새 템플릿 줄을 넣는 것은 실제 워크스페이스에서 확인 | — |

## 2026-11-18 — upgrade 를 잊지 않게: 세션 시작 안내와 자동 적용 (2.10.0)

자료: 사용 흔적 — 2.8.0 의 제외 규칙을 워크스페이스에 넣으려면 `upgrade` 를 장비마다 직접 돌려야 했다. 사용자 요청: 다른 장비에서도 잊지 않도록 유도하거나 자동으로 되게. 같은 repo 의 project-harness 플러그인이 쓰는 세션 시작 훅.

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
| 반영 | 읽기 전용 `check` 명령 + 세션 시작 훅 (`hooks/hooks.json`) | 기존 안내는 `list`·`new` 끝에만 떠서 그 명령을 돌리지 않는 세션은 놓친다. 훅은 플러그인만 갱신되면 어느 장비에서든 돈다. 임시 워크스페이스에서 사유 세 가지가 한 줄로 나오고 파일이 바뀌지 않음을 확인 | 공식 기능이 플러그인 갱신 뒤 실행할 작업을 지원하면 훅 삭제 |
| 반영 | 제외 규칙 추가는 모든 명령의 공통 준비 단계에서 자동 적용 | 줄 하나를 더하는 일이라 되돌리기 쉽고, 이 단계는 이미 `.bares/`·`tasks/` 를 만들어 준다. `upgrade` 안의 같은 블록은 삭제 (공통 단계가 먼저 채운다) | 자동 적용 항목이 셋을 넘으면 목록으로 분리 |
| 기각 | 세션 시작 때 `upgrade` 전체를 자동 실행 | 끝난 태스크를 archive 로 옮기는 동작이 있어, 세션을 여는 것만으로 폴더가 움직이면 다른 세션이 쓰던 경로가 깨진다 (사용자에게 설명 후 승인) | — |
| 기각 | 훅이 제외 규칙까지 채움 | 세션 시작만으로 파일이 바뀌면 원인을 찾기 어렵다. 훅은 읽기만 하고, 채우는 일은 사용자가 돌린 명령이 한다 | — |
| 반영 | `check` 는 `tasks/` 가 없는 루트를 워크스페이스로 보지 않음 | 루트 표식 중 하나가 `repos.txt` 라서, 같은 이름의 파일만 있는 다른 프로젝트에서 세션마다 안내가 뜰 수 있다 | — |
| 반영 | 안내 사유는 `upgrade` 가 실제로 없앨 수 있는 것만 | 표식 없이 사용자가 고친 `tasks/CLAUDE.md` 는 `upgrade` 가 건드리지 않는데 사유로 잡혀, 세션마다 같은 안내가 끝없이 떴다 (리뷰 지적, 재현 확인). `list`·`new` 끝의 안내도 같은 판정을 쓴다 | — |
| 반영 | 경로만 묻는 `root` 는 자동 적용에서 제외, 쓰기 실패는 경고 후 계속 | 읽기 전용 검색 스크립트가 `root` 를 불러 추적 파일이 조용히 바뀌었고, `.gitignore` 를 쓸 수 없으면 `root` 가 죽어 "루트 없음" 으로 오진됐다 (리뷰 지적, 재현 확인) | — |

## 2026-11-18 — task-intake 가 원문의 첨부 파일을 읽게 함 (2.8.0)

자료: 사용 흔적 — Jira·Slack 링크로 태스크를 열 때 첨부 이미지·파일이 읽히지 않아 사용자가 손으로 전달해 옴. 지금 세션의 도구 목록 (Slack 파일 읽기, Atlassian 첨부 다운로드) 을 실제 첨부로 실행해 확인.

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
| 모순 해결 | task-intake 1절의 "첨부 이미지처럼 열 수 없는 것은 미확인" 문구 삭제 | 문구가 첨부를 열 수 없는 것으로 못 박아 시도조차 막았다. 실제로는 열 수 있다 — Jira 이미지 첨부를 다운로드 작업이 준 명령으로 받아 Read 로 열었고, Slack 쓰레드의 이미지를 파일 읽기 도구로 열었다 (직접 확인) | — |
