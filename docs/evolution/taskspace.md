## 2026-11-18 — task-intake 가 원문의 첨부 파일을 읽게 함 (2.8.0)

자료: 사용 흔적 — Jira·Slack 링크로 태스크를 열 때 첨부 이미지·파일이 읽히지 않아 사용자가 손으로 전달해 옴. 지금 세션의 도구 목록 (Slack 파일 읽기, Atlassian 첨부 다운로드) 을 실제 첨부로 실행해 확인.

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
| 모순 해결 | task-intake 1절의 "첨부 이미지처럼 열 수 없는 것은 미확인" 문구 삭제 | 문구가 첨부를 열 수 없는 것으로 못 박아 시도조차 막았다. 실제로는 열 수 있다 — Jira 이미지 첨부를 다운로드 작업이 준 명령으로 받아 Read 로 열었고, Slack 쓰레드의 이미지를 파일 읽기 도구로 열었다 (직접 확인) | — |
| 반영 | 출처별 첨부 읽기 절차 (Jira·Slack·Notion) | Jira 는 `attachment` 필드에 id 가 나오고 다운로드 주소 수명이 짧다. Slack 은 쓰레드 응답의 `Files:` 줄에 id 가 나오고, 읽은 내용과 함께 저장된 파일 경로가 온다 (직접 확인). 도구 이름은 환경마다 달라 찾는 키워드만 적음 | 공식 도구가 링크의 첨부를 본문과 함께 돌려주면 절차 삭제 |
| 반영 | 첨부를 `tasks/<ID>/attachments/` 에 받고 notes.md 에 한 줄씩 기록, 첫 지시에 첨부 확인 추가 | 태스크 세션은 이 스킬을 따르지 않아 "원문을 다시 읽어 달라" 만으로는 첨부를 건너뛴다. 파일과 목록이 남아야 다시 받지 않고 열 수 있다 | — |
| 반영 | `.gitignore` 에 `archive/*/attachments/` 추가, `upgrade` 가 빠진 제외 규칙을 채움 | 진행 중에는 기존 `tasks/*/*/` 가 막지만 `done`·`hold`·`abandon` 이 폴더째 archive 로 옮기면 벗어난다. 화면 캡처는 글과 달리 개인정보를 가려 옮길 수 없어 추적하지 않는다 (사용자 승인). 기존 워크스페이스는 `init` 을 다시 돌리지 않으므로 `upgrade` 와 그 안내 검사에 넣음 | — |
| 기각 | `archive/*/*/` 로 넓게 제외 | archive 하위 폴더를 일부러 추적하는 워크스페이스가 있을 수 있다. 필요한 만큼만 좁게 | attachments 외에 archive 로 딸려 가는 미추적 폴더가 또 생기면 |
| 보류 | Notion 첨부 절차 구체화 | Notion 은 실제 첨부로 확인하지 못해 "페이지 응답의 주소로 받는다" 한 줄만 적음 | Notion 링크 수신에서 첨부를 못 읽는 사례가 나오면 |
| 보류 | 압축 파일·영상 내용 확인 | 외부에서 온 압축 파일을 자동으로 푸는 것은 위험이 있고 영상은 읽을 수단이 없다. 받아만 두고 `열지 않음` 으로 기록 | 그런 첨부가 원인 파악에 필요했던 사례가 반복되면 |
| 기록 | eval 추가 안 함 | 인증된 Slack·Jira 연결과 실제 첨부가 있어야 재현된다. 대신 실제 첨부로 도구 동작을 확인했고, 임시 워크스페이스에서 `init`·`new`·`done`·`resume`·`upgrade` 로 첨부 폴더가 추적되지 않고 함께 옮겨지는 것을 확인 | eval 이 MCP 응답을 흉내 낼 수 있게 되면 |
| 기록 | 설계 검증과 구현 검증을 한 라운드로 | 사용자가 대화 중 변경안을 보고 바로 승인해 구현 뒤 diff 로 함께 검증 | — |
