## 2026-11-19 — tmux 밖의 Herdr 터미널에서도 하위 세션을 띄움 (1.5.0)

자료: 사용자 요청 — 메신저 쓰레드에 연결된 태스크 세션이 작업 중에도 답하도록, 그 세션이 일을 하위 세션에 맡기게 하자는 것. 그 태스크 세션은 tmux 가 아니라 Herdr 터미널 (herdr-core, CLI `hc`) 에서 돌아 `spawn.sh` 가 종료코드 3 으로 멈췄다. `hc --skill` (사용 안내), `hc run --help`, Herdr 앱의 에이전트 안내 문서 (sub-agent·부모 탭 규칙), `hc` 0.1.17 실측.

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
| 반영 | 두 `spawn.sh` 에 Herdr 분기: tmux 밖이고 `$HC_TERMINAL_ID` 가 있으면 `hc run --bg --parent "$HC_TERMINAL_ID"` 로 띄움. 출력 `place=herdr terminal=<주소> name= cwd=` | 부모를 지정하면 Herdr 가 자식을 부모 탭의 sub-agent 로 기록하고, 자식이 막히면 부모에 알린다 (`hc --skill`). 실제 실행에서 `sub_agents` 에 자식 주소가 잡히고 `ListAgents` 에 보이는 것 확인 | `hc` 가 1.0 이 되거나 `run` 출력 형식이 바뀌면 |
| 반영 | tmux 가 우선 (tmux 안이면 Herdr 터미널이어도 tmux 로), tmux 경로의 동작·출력은 그대로 | 지금 쓰는 세션이 많다. 설치본 1.4.0 과 새 스크립트를 시험용 window 에서 나란히 돌려 pane·window·분기 출력 형식이 같음을 확인 | — |
| 반영 | Herdr 터미널 이름만 소문자로 (32자 넘으면 앞 23자 + 해시 8자), Claude 세션 이름은 `<부모>-<접미사>` 그대로 | `hc` 이름 규칙이 소문자·숫자·`-`·`_` 32자. 세션 이름은 `SendMessage` 주소라 tmux 때와 같아야 한다 | — |
| 반영 | `--env` 로 받은 변수는 `env K=V` 로 명령에 실음 | Herdr 터미널은 부르는 세션이 아니라 herdr-core 서버의 환경을 물려받는다 (실측) | — |
| 모순 해결 | Herdr 쪽은 `printf %q` 로 만든 명령 문자열을 쓰지 않고 인자를 그대로 넘김 (`/bin/sh -c '"$@"; exec "$0"'`) | bash 3.2 의 `%q` 는 한글 바이트 일부만 8진수로 바꿔 UTF-8 이 아닌 문자열을 만들고, `hc` 는 그런 인자를 "invalid UTF-8" 로 거부한다 (직접 확인). tmux 는 바이트를 그대로 받아 문제가 없었다 | — |
| 반영 | Herdr 에서 뜬 하위 세션은 사용자에게 직접 묻지 않고 부모에 `[질문]` (`AskUserQuestion` 도 쓰지 않음) | Herdr 의 sub-agent 는 화면 칸이 없어 사용자가 보지 못하고, 사용자는 부모와만 대화한다. 실제 자식이 흐름 안에서 끝나는 결정도 `[질문]` 으로 보내고 답을 받아 `[완료]` 한 것 확인 | Herdr 가 sub-agent 를 기본으로 화면에 보이게 하면 |
| 반영 | 문서의 Herdr 대응을 스킬마다 표 하나 (「Herdr 터미널에서」 절) 로 모음: 화면 확인 `hc read`, 닫기 `hc kill` + `hc rm`, 기록할 것은 터미널 주소 | 단계마다 tmux·Herdr 를 나란히 적으면 tmux 절차를 읽기 어려워진다 | Herdr 가 기본 경로가 되면 본문에 합침 |
| 기각 | `--outlive-parent` (부모 프로그램이 끝나도 자식 유지) | `hc` 기본값은 부모와 함께 끝나는 것. 부모 탭을 닫을 때 같이 정리되는 편이 낫고, 닫은 세션은 기록으로 재개한다 | 부모 터미널이 끝난 뒤에도 자식이 계속 가야 하는 흐름이 생기면 |
| 기각 | Herdr 에서 자식을 화면 칸으로 꺼내기 (`terminal.keep`) | 자식 수만큼 부모 탭이 나뉜다. 필요할 때 `terminal.peek` 으로 연다 | 사용자가 칸으로 보이길 원하면 |
| 정리 | Herdr 분기 코드를 두 `spawn.sh` 에 각각 둠 | repo 규칙 (스킬 자료는 스킬 디렉토리 안). 두 규약이 같이 바뀐 세 번째 회차 — 1.3.0·1.4.0 이 적은 재검토 조건에 닿았으나, 공통 스크립트를 둘 자리가 없어 (스킬 밖 참조 금지) 이번에도 복제 | 스킬 사이에 스크립트를 공유하는 공식 방법이 생기면 |
| 기록 | eval 추가 안 함 | 앞 회차와 같은 이유 (살아 있는 세션·터미널). 가짜 `claude` 로 인자·환경 변수·이름·종료코드 3·5 를, 실제 Herdr 터미널의 Claude 세션으로 띄우기 → `[시작]` → `[질문]` → 답 → `[완료]` 를 확인. 자식이 질문·권한 창에서 멈췄을 때 부모에 오는 Herdr 알림은 직접 확인하지 못함 (`hc` 안내 문서 근거) | eval 이 세션 간 메시징을 지원하면 |
| 기록 | 설계 검증은 부모 태스크의 계획 검증으로 갈음 | 이 변경을 포함한 계획이 리뷰어 2명의 적대적 검증을 거쳐 승인됐다 | — |

## 2026-11-19 — 하위 세션을 pane 으로 띄우고, 닫기 전 기록·후속 문의 때 재개 (1.4.0)

자료: 사용자 요청 — 태스크 세션에서 후속 대화·문의를 주제별로 이어갈 수 있게 하위 세션 (자식 세션·분기 세션) 을 더 자주 열고 pane 으로 보이게 하자는 제안. 작은 일이 부모 대화에 섞여, 나중에 그 건을 다시 물으면 긴 대화에서 찾아야 했다. 여는 기준·자리·끝난 뒤 처리 세 가지 계약은 부모 세션이 추천하고 사용자가 진행을 지시했다. `claude --help` 의 `--resume <세션 ID>`, tmux `split-window`·`select-layout -E`.

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
| 반영 | child-session 이 뜨는 자리: 새 window 고정 → 부모 window 의 pane 기본 | 사용자 요청. 작은 주제도 하위 세션으로 열면 window 가 빠르게 늘어 어느 태스크의 세션인지 보이지 않는다 | — |
| 반영 | 부모 말고 다른 pane 이 이미 3개면 새 window (`--window` 로 강제도 가능), 나눌 공간이 없어도 window 로 넘김 | 더 나누면 폭이 좁아 diff·표가 깨진다. 세는 대상은 하위 세션 pane 만이 아니라 그 window 의 다른 pane 전부 — 이유가 폭이라서 사용자가 연 셸도 같다 | 화면 폭이 달라져 3개가 맞지 않으면 숫자 조정 |
| 반영 | 배치: 첫 pane 은 부모 오른쪽, 그다음은 오른쪽 열을 위아래로 나누고 높이를 고르게 폄 | 매번 부모 pane 을 반으로 나누면 부모 폭이 176 → 88 → 44 로 준다. 실제 실행에서 부모 176 유지, 오른쪽 열 28/28/28 확인 | — |
| 반영 | side-task 도 같은 배치·같은 3개 기준 (**기존 동작 변경**: 전에는 매번 부모 패널 옆을 나눴고 window 로 넘어가지 않았다) | 하위 세션의 자리 규칙이 스킬마다 다르면 pane 수를 한 기준으로 셀 수 없다. 두 번째 분기부터 부모 폭이 주는 문제도 같이 풀린다 | — |
| 반영 | 닫기 전 기록 (`## 하위 세션` 절에 세션 이름 · 세션 ID · 맡은 주제 · 작업 디렉토리) 과 `--resume` 재개 절 | 닫은 세션은 이름만으로 다시 찾기 어렵다. 작업 디렉토리는 계약의 세 항목에 더한 것 — 재개는 세션이 떴던 디렉토리에서만 대화를 찾는다 (부모 세션 동의). 재개 뒤 세션 ID 가 그대로이고 닫기 전 대화를 기억함을 실제 실행으로 확인 | 공식 기능이 닫은 세션을 이름으로 재개하게 되면 기록 항목 축소 |
| 반영 | 하위 세션이 `[시작]` 에 세션 ID 를 보고 | 부모가 기록할 ID 를 얻을 길이 없었다. `[완료]` 가 아니라 `[시작]` 인 이유: 하위 세션이 중간에 죽어도 재개할 수 있게 | — |
| 정리 | 닫기를 `kill-pane` 하나로 통일, 닫기 후보의 "window 에 pane 하나" 조건 제거 | `kill-pane` 은 그 pane 만 닫고, window 에 혼자면 window 도 닫힌다. 자식이 연 패널이 함께 닫히는 문제 (1.3.0 의 조건이 막던 것) 가 없어진다. 대신 하위 세션의 닫기 확인에 "자기가 연 하위 세션이 모두 닫혔다" 를 더함 — 남으면 보고가 갈 곳이 없다 | — |
| 반영 | child-session 의 맞는 일에 "따로 이어 물을 주제 (PR · 문의 답변 · 조사 하나)" | 사용자 요청의 여는 기준. 언제 여는지의 상세는 사용자 전역 문서가 정하고 스킬은 고르기 표와 description 만 맞춘다 | — |
| 기각 | 하위 세션 pane 에 표식 (tmux pane 옵션) 을 달아 그것만 세기 | 표식 없는 기존 pane·손으로 연 pane 을 놓치고, 폭 문제는 어떤 pane 이든 같다 | — |
| 정리 | 자리 고르기 코드를 두 `spawn.sh` 에 각각 둠 | repo 규칙 (스킬 자료는 스킬 디렉토리 안). 두 규약이 같이 바뀐 것은 이번이 두 번째 (1.3.0 의 `--` 수정, 이번) | 세 번째로 같이 바뀌면 공통화 방법 재검토 (1.3.0 기록과 같은 조건) |
| 기록 | eval 추가 안 함 | 앞 회차와 같은 이유 (tmux 의 살아 있는 세션). 시험용 window 에서 실제 세션으로 검증 — 자식 3개 pane · 4번째 window · 닫기 · 세션 ID 로 재개 · 없는 ID 는 종료코드 4, 분기 세션도 pane · 닫기 · 재개 | eval 이 tmux·세션 간 메시징을 지원하면 |
| 기록 | 설계 검증 없이 구현 검증만 | 계약 세 가지를 부모 세션이 정해 브리프로 넘겼고 `[시작]` 계획을 부모가 확인했다 | — |

## 2026-11-17 — child-session 스킬 추가 (1.3.0)

자료: 사용 흔적 — 업무 태스크 하나를 흐름 5개 (repo·worktree 가 서로 다름, 흐름마다 사용자 결정·운영 배포 확인) 로 나눠 손으로 새 세션을 띄우고 브리프 파일 하나로 맡긴 사례. 같은 날 겪은 문제: 같은 이름의 부모 세션 둘 (자식이 보고를 엉뚱한 부모에게 보냄), 여러 세션이 같은 기록 파일을 고침, 전역 규칙이 바뀌어도 떠 있는 세션은 옛 규칙으로 일함. side-task 스킬 (1.2.0) 의 분기 방식과 비교 (사용자 요청).

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
| 반영 | child-session 스킬 (새 세션 + 브리프 + 새 window + 보고 규약 + 전파 + 닫기 판단) | 몇 시간~며칠 가는 흐름에서는 분기의 장점 (인계 손실 없음) 보다 단점이 크다 — 부모만큼 찬 컨텍스트로 시작해 곧 compact, 매 턴 부모 대화를 함께 실음, 기록이 대화에만 남음. 브리프는 계약·compact 뒤 재시작 지점이 되고, 인계 손실은 브리프가 결정 로그를 가리키고 `[시작]` 계획 요약을 부모가 확인해 줄인다 | 공식 기능이 브리프를 받는 자식 세션 띄우기·보고를 제공하면 deprecate |

## 2026-11-16 — side-task 스킬 추가 (1.2.0)

자료: 사용 흔적 — 업무 태스크 세션에서 곁가지 작업을 손으로 분기한 세션 (`<부모>-<접미사>` 이름, 같은 tmux window 의 패널) 이 잦고, 분기 세션이 부모와 같은 git checkout·같은 기록 파일을 써서 한 브랜치에 무관해 보이는 커밋이 함께 놓인 사례. `claude --help` 의 `--resume` + `--fork-session` + `-n`, 공식 `SendMessage`·`ListAgents`.

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
| 반영 | side-task 스킬 (fork + 옆 패널 + 보고 규약 + 닫기 판단) | 맥락을 이어받는 분기는 공식 `--fork-session`, 보고는 공식 `SendMessage` 로 되지만 패널 분할·git 분리·공유 기록 파일 단일 작성자·닫기 판단을 묶는 절차가 없다 | 공식 기능이 fork 세션을 패널로 띄우고 부모에게 보고하게 되면 deprecate |
| 반영 | 플러그인 위치 = sessions | "세션 관련 도구 묶음" 취지에 맞고 설치 목록이 늘지 않는다 (사용자 결정). 플러그인 전체 deprecated 표시를 떼고 crosstalk 소개에만 남김 (deprecation.md 2번 "일부만이면") | — |
| 반영 | 완료 후 패널은 남기고 부모가 닫기를 판단 | 사용자 결정. 부모가 남은 일·미답 질문·worktree 미커밋을 보고 후보를 정하고, 분기 세션이 `닫아도 됨` 이라고 답할 때만 닫는다 (분기 세션 진행 상태는 부모가 볼 수 없음) | 닫기 확인 왕복이 매번 형식적으로만 오가면 단순화 |
| 기각 | 분기 세션 worktree 기본 위치 (`<checkout>-<접미사>`) | 하위 디렉토리를 repo 로 세는 워크스페이스 (taskspace `tasks/<ID>/*/`) 에서 hold·resume·link 가 오동작. 워크스페이스 규칙 > 사용자에게 묻기 | — |
| 보류 | taskspace 에 곁가지 worktree 위치 규칙 추가 | 지금은 분기 세션이 묻는 것으로 충분 | 분기 세션이 taskspace 에서 위치를 반복해서 묻게 되면 |
| 기록 | crosstalk 삭제 재검토의 대상 | 앞 회차의 "deprecate 후 60일" 삭제는 이제 **crosstalk 스킬만** 대상이다. 플러그인은 side-task 때문에 남긴다 | — |
| 기록 | eval 추가 안 함 | tmux 안의 살아 있는 세션 두 개와 메시지 왕복이 필요해 eval 샌드박스로 재현할 수 없다. 구현 때 실제 분기 스모크 두 번 (맥락·이름·닫기 / git 분리·공유·질문·닫지 않음) 으로 검증 | eval 이 tmux·세션 간 메시징을 지원하면 |

## 2026-10-06 — crosstalk 를 공식 세션 간 메시징으로 대체 (1.1.0)

자료: Claude Code CHANGELOG (https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md — 2.1.224 cross-session `SendMessage`, 이후 provider 확장·`--restricted` 수정), 공식 문서 https://code.claude.com/docs/en/cross-session-messaging · https://code.claude.com/docs/en/settings-reference#crosssessioninbound, 로컬 세션의 `SendMessage`·`ListAgents` 도구 정의. 정기 sweep 첫 실행이 후보로 올림.

| crosstalk 기능 | 공식 기능 | 빠지는 것 |
|---|---|---|
| `recv --name` 이름 등록 (충돌 시 접미사) | `/rename`·`--name`, 자동 이름 | 없음 |
| Monitor 상주 수신 대기 | 수신함 기본 켜짐, 다음 도구 라운드에 전달 | 없음 |
| `send` (600자 넘으면 spool 파일) | `SendMessage`, 본문 전체 | 없음 |
| `list` (이름·cwd) | `ListAgents` (이름·cwd·상태) | 없음 |
| disconnect | `/config` "Messages from your other sessions" (v2.1.232+) | 끄는 범위가 세션이 아니라 사용자 전체 |
| `fyi:` 핑퐁 방지 규약 | 보낸 쪽별 제한·중복 제거·대기 상한 | 없음 |

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
| deprecate | crosstalk 스킬 | 이름 지정 (`/rename`)·보내기 (`SendMessage`, 본문 전체)·목록 (`ListAgents`)·수신 (기본 켜짐)·수신 끄기 (`/config` "Messages from your other sessions") 가 모두 공식 기능과 겹침. v2.1.224 이상이면 따로 켤 것 없음 | 삭제: deprecate 후 60일 + 그 기간 memory·이슈에 crosstalk 언급 없음 |
| 기각 | deprecate 연기 (권한 모드 차이) | 모드가 다른 세션끼리는 메시지마다 승인 창 (5분 뒤 버림) 이 뜨지만 `crossSessionInbound: "accept"` 로 풀리는 설정 차이 — 안내 문구에 남김 | `crossSessionInbound` 가 관리자 전용 설정으로 바뀌면 |
| 기각 | 이름 지정·수신 대기·`fyi:` 핑퐁 방지 규약 차이 | 공식 문서가 보낸 쪽별 제한·중복 제거·대기 상한으로 반복을 막음. 수신 끄기는 사용자 전체에 적용되는 차이만 남음 | 세션 하나만 수신을 끄는 일이 반복해서 필요해지면 |
| 기록 | eval 추가 안 함 | 동작 변경 없이 안내 문구·표시만 추가 | — |
