## 2026-11-20 — 야간 배포 차단을 맡는 훅이 deploy-guard 플러그인으로 옮겨짐 (1.1.0)

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
| 반영 | 세션 시작 때 표시 파일을 남기는 훅 (`hooks/mark-session.sh`) | 설정의 훅 블록을 지우면 떠 있는 세션이 그 훅을 즉시 잃는다 (2.1.329 실측) — 1.0.0 으로 옮길 때 그 빈 곳이 생겼다. 설정 쪽 훅이 이 표시가 없는 세션에서만 옮기기 전 스크립트를 돌리게 해 메운다 | 옮기기 전에 시작한 세션이 모두 닫히면 설정의 블록 삭제 |
| 반영 | README 「이 플러그인이 하지 않는 것」 에 배포 점검 훅의 새 위치 (`deploy-guard`) 를 적음 | 아래 회차의 재검토 조건 (배포 확인 장치가 플러그인으로 옮겨지면 README 갱신). 동작 변경 없음 | 질문 점검 훅이 옮겨지면 같은 줄 갱신 |

## 2026-11-20 — 개인 설정 저장소에 있던 야간 루프를 플러그인으로 추출 (1.0.0)

자료: 사용자 요청 — 전역 하네스 (훅·스크립트·문서) 가 개인 설정 저장소에 있어 그 저장소를 깔 수 없는 장비에서는 쓸 수 없으니, 작업 장치를 플러그인으로 옮기자는 것. 야간 루프가 가장 독립적이라 첫 번째다. Claude Code 2.1.329 실측 (플러그인 훅의 환경 변수 · `timeout` · 로컬 로드), 공식 문서 (설치본 경로 · 버전 해석 · `bin/` PATH · 설치 훅 없음), 리뷰어 2명의 계획 검증.

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
| 반영 | 러너 · 야간 가드 · 검증 게이트 · 지시문 2개를 그대로 옮김. 훅 matcher · timeout 은 옮기기 전 값 그대로 | `tests/run.sh` 를 옮기기 전 스크립트와 새 스크립트에 같은 기대값으로 돌려 둘 다 통과 | — |
| 반영 | 고정 경로의 실행 파일 (`~/.local/bin/claude-loop`) 을 링크가 아닌 작은 스크립트로 두고 실행 때마다 러너를 찾음 | 설치본 경로가 버전마다 바뀌고 옛 버전 폴더는 지워진다 (공식 문서). launchd 는 고정 경로가 필요하다 | Claude Code 가 세션 밖에서 쓸 플러그인 고정 경로를 제공하면 |
| 기각 | 세션 시작 훅이 실행 파일 링크를 갱신하는 방식 | 링크 판정 규칙이 복잡해지고 (끊김 · 다른 버전 · 설치본 아닌 폴더), 세션이 오래 시작되지 않은 장비에서는 끊긴다 | — |
| 반영 | 장비마다 다른 값 (워크스페이스 루트 · 토큰 불러오기) 을 `~/.config/claude-loop/env` 로 | 옮기기 전에는 러너에 고정 경로로 박혀 있었다. 야간 가드가 이미 이 폴더를 보호한다. 파일을 읽다 실패하면 로그와 알림을 남긴다 | — |
| 반영 | 야간 가드 보호 대상에 플러그인 폴더 자신 (불린 경로와 실경로 둘 다) | 설치본은 Claude 설정 폴더 아래라 이미 막히지만, 다른 폴더에서 실으면 야간 세션이 가드를 고칠 수 있다. 환경 변수가 아니라 스크립트 위치에서 구해 어떻게 불려도 같다 | — |
| 반영 | 야간에 `claude-loop end · approve · install · uninstall` 은 확인창 | `end` 는 야간 상태를 지우고 `approve` 는 검증 명령을 스스로 승인하는 길 — 옮기기 전부터 열려 있던 구멍 (계획 검증에서 발견) | — |
| 모순 해결 | `approve` 가 opt-in 줄이 여러 개일 때 조용히 죽던 것 | `listEntries \| awk '… exit'` 에서 awk 가 먼저 끝나 앞 명령이 SIGPIPE 로 죽고 pipefail 이 스크립트를 끝냈다 (시험에서 발견). 목록을 변수에 받아 끝까지 읽게 함 | — |
| 반영 | 질문 지표는 PATH 의 `loop-metrics` 명령으로 부름 | 지표 스크립트는 다른 장치 (질문 줄이기) 의 것이라 옮기지 않았다. 경로로 받으면 그쪽이 플러그인이 됐을 때 버전마다 낡는다 | 지표 스크립트가 플러그인으로 옮겨지면 연결 방식 확인 |
| 보류 | 상황판 (`board`) 을 러너에 그대로 둠 | 꼬리표 파일을 쓰는 것은 멈춤 점검 훅이라 본래 그쪽 몫. 이번 범위는 야간 루프 | 멈춤 점검 훅이 플러그인으로 옮겨질 때 함께 옮김 |
| 보류 | 야간 배포 차단 · 야간 질문 차단은 이 플러그인 밖 (같은 판정 조건을 읽는 다른 훅) | 그 훅들은 낮에도 일하는 다른 장치다. README 에 판정 조건과 빈 곳을 적음 | 배포 확인 · 질문 점검 장치가 플러그인으로 옮겨지면 README 갱신 |
| 보류 | 버전 규칙 (이 플러그인만 `version` 을 빼 커밋을 버전으로) | 문서 근거뿐이고 실측하지 못했으며, 자동 갱신이 마켓플레이스 등록 설정에 달려 있다. 이 플러그인은 자주 바뀌지 않아 지금 규칙의 부담이 작다 | 더 자주 바뀌는 플러그인을 추가할 때 git 소스 마켓플레이스로 실측 |
| 보류 | 개발 장비에서 작업 폴더를 바로 싣기 | 공용 설정에 장비 경로를 넣으면 그 경로가 없는 장비에서 훅이 조용히 빠진다. 시험은 `--plugin-dir` 로 충분했다 | 위 버전 규칙을 정할 때 함께 |
| 기각 | launchd 라벨 이름 변경 | 소유자 이름은 repo 규칙이 금지하는 회사·프로젝트 이름이 아니고, 바꾸면 옮기는 단계만 늘어난다 | 다른 사람이 쓰게 되면 |
| 기록 | eval 추가 안 함, `tests/run.sh` 로 대신 | 훅과 러너는 모델 판단이 아니라 셸 판정이다. 격리한 HOME 과 가짜 `claude` · `tmux` · `launchctl` 로 훅 판정 · 전달 경로 · 설치 · 실행 파일을 84건 확인 | — |
| 기록 | 실제 야간 실행은 이 회차에 한 번도 돌지 않음 | 옮긴 장비에서 야간 실행이 꺼져 있고 승인된 세션이 없었다. 전달 경로는 가짜 명령으로만 확인 | 야간 실행을 다시 켠 첫 밤에 로그 확인 |
