## 2026-11-20 — 개인 설정 저장소에 있던 배포 확인 장치를 플러그인으로 추출 (1.0.0)

자료: 사용자 요청 — 전역 하네스의 작업 장치를 플러그인으로 옮기는 일의 두 번째. Claude Code 2.1.329 실측 (설정의 훅 블록을 지우면 떠 있는 세션도 그 훅을 즉시 잃는다), 리뷰어 2명의 계획 검증.

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
| 반영 | 배포 점검 훅 · QA 알림 훅을 판정 코드 그대로 옮김. matcher · timeout 도 옮기기 전 값 | 운영 배포 앞의 안전 장치라 옮기면서 판정을 바꾸지 않는다. `tests/run.sh --legacy` 가 옮기기 전 스크립트와의 차이가 주석 · 안내문 · 변수 한 줄뿐인지 기계로 확인하고, 양쪽에 같은 기대값 (71 · 75건) 을 통과 | — |
| 반영 | 승인 위임 세션을 가리는 환경 변수를 일반 이름 `CLAUDE_DEPLOY_APPROVED_SESSION` 으로 | 옮기기 전에는 특정 봇 프로젝트의 이름이 든 변수였다 (공개 플러그인에 넣을 수 없음). 세션을 띄우는 쪽이 새 변수를 함께 넘긴다 | — |
| 기각 | 그 변수 이름을 저장소 밖 파일이나 대상 파일의 줄에서 읽기 | 늘 값이 있는 변수 이름 한 줄이면 모든 운영 확인이 꺼진다. 대상 파일에 새 줄 종류를 넣으면 옮기기 전 스크립트가 형식 오류로 보아 떠 있는 세션이 엄격한 판정으로 떨어진다 | — |
| 반영 | 절차 문서 전문을 스킬 `deploy` 로 | 훅 안내문이 가리킬 곳이 플러그인 안에 있어야 한다. 프로젝트 이름이 든 한 문장과 설정 저장소에 묶인 문장만 일반화 | — |
| 반영 | `/deploy-guard:setup` 은 정책 파일 자리 잡기만, 예시를 복사하지 않음 | 형식만 맞는 가짜 파일이 생기면 파일이 없을 때의 엄격한 판정이 풀린다 (계획 검증) | — |
| 보류 | 분류 표를 모델에 싣는 것 (전역 지시 파일의 불러오기 줄) | 전역 지시 파일을 만드는 것은 취향 규칙 플러그인의 몫이다. 표가 없어도 훅은 대상 파일로 판정한다 | 취향 규칙 플러그인을 만들 때 |
| 보류 | 훅이 오류로 끝날 때 막는 쪽으로 바꾸기 | 필요한 명령이 없는 장비에서 모든 Bash 호출이 막힌다. 옮기기 전과 같은 동작으로 둠 | 오류 종료가 실제로 명령을 통과시키는지 실측한 뒤 |
| 보류 | 정책 파일에 커밋 안 된 변경이 있으면 엄격한 판정, 안내문에 정책 파일의 마지막 커밋 표시 | 둘 다 판정 코드 변경이라 "바꾸지 않고 옮긴다" 와 함께 할 수 없다 | 옮긴 뒤 별도 회차 |
| 기록 | 옮기는 동안 설정의 훅 블록을 지우지 않음 | 지우면 떠 있는 세션이 훅을 즉시 잃는다 (실측). 플러그인이 세션 시작 때 표시 파일을 남기고 (`hooks/mark-session.sh`), 설정 쪽 명령은 그 표시가 없는 세션에서만 옮기기 전 스크립트를 돌린다. 세션 기록 파일의 생성 시각으로 가르는 안은 버렸다 — 옮기기 전에 열어 두고 첫 입력을 뒤에 한 세션이 훅 없이 남는다 | 옮기기 전에 시작한 세션이 모두 닫히면 설정의 블록과 옮기기 전 스크립트 삭제 |
| 기록 | eval 추가 안 함, `tests/run.sh` 로 대신 | 훅은 모델 판단이 아니라 셸 판정이다 | 스킬 `deploy` 의 호출 여부를 재고 싶어지면 |
