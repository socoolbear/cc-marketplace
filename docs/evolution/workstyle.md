## 2026-11-20 — 취향 규칙 (지시문 · 문서) 을 플러그인으로 추출

자료: 같은 날 앞 회차의 계획 (두 번에 나눈 것의 둘째). Claude Code 2.1.329 실측 — 훅으로 넣은 지시문은 서브에이전트에 실리지 않고, 전역 지시 파일과 그 import 는 실린다. 상대 import 는 심링크의 실제 위치 기준으로 풀린다. 리뷰어 2명의 계획 검증, 사용자 결정 (개발 장비는 규칙 글만 체크아웃 심링크).

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
| 반영 | 지시문 3개와 문서 4개를 `rules/` 로 옮기고, 고정 폴더 `~/.claude/workstyle` 를 전역 지시 파일이 홈 기준 경로로 불러옴 | 설치본 경로는 커밋마다 바뀌어 import 대상이 될 수 없다. 전역 지시 파일의 import 는 서브에이전트에도 실린다 (실측) | 플러그인이 지시문을 싣는 공식 수단이 생기면 |
| 반영 | 일반 장비는 세션 시작 훅 (`sync-rules.sh`) 이 사본을 맞추고, 개발 장비는 고정 폴더를 체크아웃 심링크로 | 사용자 결정. 매일 고치는 글을 push · 갱신 없이 바로 쓰려는 것. 훅은 심링크와 남의 폴더를 건드리지 않는다 | 규칙 글과 훅이 어긋나 문제가 되면 |
| 반영 | 공개 저장소에 넣을 수 없는 규칙은 지우지 않고 저장소 밖 장비 규칙 파일 (`~/.config/claude/local-rules.md`) 로 | 프로젝트 지시 파일로 옮기면 그 프로젝트 밖 세션에서 규칙이 사라진다 (계획 검증). 제품 이름이 든 규칙은 그대로 둠 | — |
| 기각 | 문서 4개를 스킬로 | 워크플로우 표가 경로를 짚어 "먼저 읽는다" 로 부르고, 스킬을 부를 수 없는 에이전트 (Codex) 도 경로로는 읽는다 | — |
| 기각 | 파일 이름 `CLAUDE.md` | 체크아웃에서 프로젝트 지시로 한 번 더 실린다. `workflow-table.md` 로 둠 | — |
| 기록 | 일반 장비에서 규칙 갱신이 한 세션 늦을 수 있음 | 세션 시작 훅과 지시문 로드의 순서를 실측하지 못했다 | 순서를 실측하면 README 갱신 |

## 2026-11-20 — 개인 설정 저장소에 있던 작업 훅 · 에이전트 · 명령 · 상황판을 플러그인으로 추출

자료: 사용자 요청 — 전역 하네스의 작업 장치를 플러그인으로 옮기는 일의 세 번째. 매일 고치는 파일이 많아 두 번에 나눴고 이 회차는 훅 · 에이전트 · 명령이다 (취향 규칙은 다음 회차). Claude Code 2.1.329 실측, 리뷰어 2명의 계획 검증, 사용자 결정 2건.

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
| 반영 | 작업 훅 7개를 판정 코드 그대로 옮김. 이벤트 · matcher · timeout 도 옮기기 전 값 | `tests/run.sh --legacy` 가 옮기기 전 스크립트와 나란히 돌려 종료 코드 · 출력이 같은지, 파일 차이가 주석 · 문서 경로 · 훅끼리 부르는 경로뿐인지 확인 (59건) | — |
