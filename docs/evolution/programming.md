## 2026-11-05 — 크래시 자동 판정 제거, 회전 규칙 보강 (2.3.0)

자료: 2.2.0 수정분 리뷰 4라운드.

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
| 제거 | 크래시 표시로 자동 DLQ 보내는 규칙 (2.1.0·2.2.0) | 프로세스 안에서는 종료 원인이 메시지인지 가릴 수 없다. "혼자 재처리" 는 정의가 안 되고, 고치려면 공유 저장소·lease·상태 기계가 필요하다. 세 번째 수정이라 규칙을 없앴다 | 자동 격리 요구가 실제 사고로 나오면 |
| 반영 | 위치 로그 + 재시작 반복 경보 + `dlq quarantine` | 사람이 격리한다. 커밋 위치 앞 구간은 offset 순서대로 Sink 에 다시 쓴 뒤 커밋한다 (토픽 끝 재투입은 순서가 뒤집힌다) | — |
| 모순 해결 | 재시작 반복 경보식을 namespace·container 합계로 | 범인 메시지가 옮겨 다니면 파드별 식이 안 울린다 | — |
| 반영 | 회전: inode 가 다르면 0 부터, 옛 fd 는 EOF 가 이어질 때 닫기, Backpressure 중에도 감지, 재시작 때 회전 파일 탐색 | 리뷰 지적. 첫 EOF 에 닫으면 재오픈 전 쓴 줄을 잃는다 | — |

이 회차는 eval 을 돌리지 않았다. 마지막 리뷰의 지적 1건 (격리 구간 재투입 순서) 은 반영한 뒤 재리뷰하지 않았다.

## 2026-11-05 — 크래시 표시 규칙, 회전 감지 (2.2.0)

자료: 마지막 수정 리뷰, `q-hard-log-tail-shipper` 답변 6개의 코드 분석 (일부 실행 확인).

| 판정 | 항목 | 근거 | 재검토 조건 |
|---|---|---|---|
| 모순 해결 | 크래시 표시: 소유자를 넣고 혼자 다시 처리해 또 죽을 때만 센다 | OOM·SIGKILL 과 다른 인스턴스의 처리 중 표시까지 세면 정상 메시지가 DLQ 로 간다 | — |
| 반영 | tailer 는 주기마다 경로와 fd 의 dev·inode 를 비교, fingerprint 여도 크기 비교 유지 | 답변 1건이 fingerprint 만 믿고 create 회전 뒤 새 파일을 한 주기 못 읽었다 (실행 확인). 스킬 문구가 원인이라는 것은 추정 | — |
| 보류 | `checkpoint-after-durable-ack` 기준 완화 ("200 뒤 세그먼트 삭제, 재시작 시 세그먼트로 복구" 허용) | 실패 1건이 채점 오류로 추정되지만 심판 사유가 없고, 결과를 본 뒤 스킬에 유리하게 기준을 바꾸게 된다 | 다음 `hard` 측정 전에 기준을 먼저 고칠 때 |

분석 한계: 심판 사유와 실행 기록이 없어 references 를 읽었는지 알 수 없다. 실패 2회가 Go, 통과 4회가 Python 이라 언어 교란이 있다. Δ -0.22 는 스킬 효과로 단정하지 않는다. 이 회차는 eval 을 돌리지 않았다.

## 2026-11-05 — CBD 컴포넌트 카탈로그, 이름 변경 (2.0.0)

자료: 사용자 제공 2013년 사내 기술 문서 (로그 수집 에이전트 + 수집 서버, 35쪽), 공식 문서·RFC·소스 조사 (각 reference 에 링크), eval 결과.

진단: 원칙 (crash-only, 멱등, 확인 응답 순서) 은 충실하고 자료보다 현대적이었다. 빠진 것은 조립 단위였다. 규칙 모음이라 "무슨 컴포넌트를 두고 무엇을 플랫폼에 맡기나" 를 답하지 못했고, Plugin Interface·Transfer·CLI Component 는 사실상 없었다.
